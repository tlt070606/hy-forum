# 小程序端人工验证清单（M2 验收项 §5.5）

> **谁做这个**：需求方本人。这是 M2 里**唯一 Agent 做不了、命令也顶替不了**的验收项 ——
> 它需要点 GUI、看渲染结果，而"构建成功""E2E 通过"都不能证明小程序端能用。
>
> **为什么不能省**：小程序端没有 XHR、没有 DOM、条件编译是**文本替换**而非运行时判断，
> 这些问题在 H5 上全都不会暴露。H5 跑通、小程序白屏，是这个技术栈最常见的失败方式。
>
> 最后更新：2026-09-15

### 0.1 🔴 必须用 **dev** 产物，不能用 build 产物（2026-09-16 实测踩到）

```bash
cd D:\demo\Hy论坛\web
npm run dev:mp-weixin          # ← 开发模式。→ web/dist/dev/mp-weixin
```

> ⛔ **不要用 `npm run build:mp-weixin`，也不要打开 `dist/build/mp-weixin`。**
>
> **为什么（这是有意的守卫，不是 bug）**：`uni build` 对**任何平台**都按 production 模式运行，
> 于是 `import.meta.env.PROD === true`。而 `src/utils/env.ts` 第 167 行有一条**刻意加的**启动期校验：
>
> ```ts
> if (IS_PROD && protocol !== 'https:') {
>   throw new Error(`[env] 生产构建要求 https，当前为 "${protocol}"。` +
>     '原因：小程序端只允许已备案 HTTPS 域名；安卓端默认拒绝明文 http。' +
>     '（ADR-0011 C2 —— 这不是可以"先上线回头再改"的事项）')
> }
> ```
>
> 本地后端是 `http://127.0.0.1:8080` → 撞上这条 → **应用一启动就抛错**，
> 界面上的表现是「无法获取注册状态：[env] 生产构建要求 https」，
> 而**一个网络请求都不会发出**（所以 Network 面板是空的 —— 别去查域名白名单，那不是原因）。
>
> **踩坑时最容易搞错的判断**：这条红字**不是**微信的「不在 request 合法域名」校验，
> 是**我们自己的代码**抛的。区分方法：微信的提示里会出现"合法域名"字样，
> 而这条里出现了 `ADR-0011 C2` —— 那是本项目自己的文档编号。
>
> **为什么不能"把那个判断注释掉"**（有人在网上会给这个建议）：那条守卫拦的正是
> **"打包出指向 http 的正式产物"** 这个真实事故 —— 小程序正式版连不上、
> 安卓拒绝明文。注释掉它 = 把一个响亮的启动失败换成**静默不能用的应用**。
> 本地要用，正确的做法是**用 dev 模式构建**，而不是削弱守卫。
>
> （`src/utils/env.ts` 第 93–112 行的注释记着：这个坑在 M2 期间**已经踩过一次**
> —— 当时是「绿构建、白屏应用」，随后才把地址选取逻辑改成"优先绝对地址、回退本机地址"。
> 现在剩下的这条 https 校验是**有意保留**的最后一道。）

> ⚠️ `npm run dev:mp-weixin` 是**常驻**进程（带热更新），不要等它退出 —— 让它开着，
> 然后在开发者工具里打开 `dist/dev/mp-weixin`。它一重建，工具里会自动刷新。

## 1. 打开项目（只要做一次）

1. 启动 `D:\Program Files\微信web开发者工具\微信开发者工具.exe`
2. 选「**导入项目**」（或「打开项目」）
3. **目录**填（**必须是 dev 产物**，理由见 §0.1 —— 填 `dist/build/...` 会必然报错）：
   ```
   D:\demo\Hy论坛\web\dist\dev\mp-weixin
   ```
4. **AppID 这一栏是本清单最容易卡住的地方**：

   | 情况 | 怎么做 |
   |---|---|
   | 你有小程序**测试号** | 直接填它的 AppID |
   | 该目录已有 `project.config.json`，里面是 `wxbb99df266b916354` | 如果那是你自己的测试号，用「打开项目」直接沿用，不用重填 |
   | 什么都没有 | 在 AppID 栏选「**测试号**」（无需注册主体）；实在不行用「游客模式」 |

   > ⚠️ **两个产物目录的 appid 来源不同（2026-09-16 实测）**：
   >
   > | 产物 | appid | 谁写的 |
   > |---|---|---|
   > | `dist/build/mp-weixin` | `wxbb99df266b916354` | **微信开发者工具**（打开项目时写进去的） |
   > | `dist/dev/mp-weixin` | **`touristappid`** | **构建生成的默认值** |
   >
   > 所以你导入 **dev** 产物时，AppID 栏大概率显示 `touristappid`（游客模式）——
   > 要么直接用它（游客模式在模拟器里可用），要么填你自己的测试号。
   > 这也解释了老记忆文件里"appid 是 touristappid"那句话为什么与实际产物不一致：
   > **它说的是构建生成的那一份，而当时看的是工具改过的那一份。**
   >
   > 两个目录都被 `.gitignore` 排除，所以 **AppID 不受版本控制**（这是对的 —— 不该进仓库）。
   > 后果：换台机器、或删掉 `dist/` 重新构建之后**会回到 `touristappid`**，需要在这里重填一次。
   > 如果你希望它固定下来，把 AppID 写进 `src/manifest.json` 的 `mp-weixin.appid`
   > （AppID 不是密钥，可以进仓库；**AppSecret 绝对不行** —— 铁律 5）。

5. 右上角「**详情**」→「**本地设置**」→ 勾上：

   ```
   ☑ 不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书
   ```

   > 产物里已写 `urlCheck: false`，但**界面上的勾要亲眼确认一遍** ——
   > 这份文件是工具生成的，不同版本对它的处理不一样。
   > **忘了这一条，现象是"所有请求都失败、页面显示暂无数据"**，非常像业务逻辑坏了。

## 2. 要看的 11 件事（逐条打勾）

> 每条都写清「预期」与「这一条在防什么」。**看到预期之外的结果就记下来，不要自己解释掉。**

| # | 操作 | 预期 | 这一条在防什么 |
|---|---|---|---|
| 1 | 刚编译完看首屏 | **是「登录 / 注册」页**：能输入用户名、密码、图形验证码 | 启动页必须是登录页（`pages.json` 的第一项）。**白屏 = 小程序端炸了**，这是最容易发生的失败 |
| 2 | 看验证码图片 | 显示一张 4 位验证码图；**点它应该刷新出一张新的** | 验证码是 base64 图片，小程序端 `image` 组件渲染 base64 的路径与 H5 不同 |
| 3 | 看底部 tabBar | 有「首页」「我的」两个，能点着切 | tabBar 是 `pages.json` 配置，小程序端会检查 `tabBar` 里的 `iconPath` —— 缺图标文件会**整个编译失败或白屏** |
| 4 | 切到「注册」Tab | 出现注册表单：用户名 / 密码 / 昵称 / 验证码 / 协议勾选 | 注册模式是**后端动态给的**（`GET /api/auth/register-mode`）。如果后端返回 `closed`，注册入口**应该不显示**。若此时后端 Redis 不在，会走兜底 |
| 5 | **真的注册一个新账号** | 提交后**自动切到登录 Tab，且没有直接登录进来** | 契约里 `register` **只返回用户信息、不返回 token**。如果注册完直接进了首页，说明有人给前端加了"注册即登录"的臆测行为 |
| 6 | 用刚注册的账号登录 | 进入「我的」，显示你填的昵称与 `@用户名` | 全链路：`uni.request` → Sa-Token 头 → `/api/user/me` |
| 7 | **关掉开发者工具，再重新打开项目** | 仍是登录态，「我的」页还是你的信息 | 这条最关键：验证 token 真的写进了**小程序本地存储**（`uni.setStorageSync`），而不是只活在内存或 `localStorage` 里（**小程序没有 `localStorage`**，写错就只在这里暴露） |
| 8 | 在「我的」页点「退出登录」 | 弹确认框；确认后**回到登录页**，再次进入「我的」显示"你还没有登录" | 退出必须清本地 token，无论服务端注销成不成功 |
| 9 | **把后端停掉**（关掉 IntelliJ 里那个进程），再点登录 | 出现**可读的中文提示**（"网络连接失败，请检查网络后重试"之类），**不是白屏、不是错误码、不是一堆英文** | 离线兜底。小程序端拿不到响应时的报错形状与 H5 不同 |
| 10 | 打开「用户协议 / 隐私政策 / 免责声明」三个页面 | 都能打开读到内容，且**顶部有"尚未定稿"的醒目提示** | 这三份是结构模板，**不是法务定稿**，别当成已完成的合规文本 |
| 11 | 看开发者工具的 **Console** 面板 | **没有红色报错**；不应有 `request:fail`、`Cannot read property of undefined` | 小程序端很多错误**不弹提示、只是不显示**，只能靠 Console 看到 |

## 3. 这些现象**不是** bug（别去追）

| 现象 | 原因 | 怎么处理 |
|---|---|---|
| 所有请求都失败 / 一直"暂无数据" | 忘了勾「不校验合法域名」 | 回去做 §1 第 5 步 |
| 真机预览连不上后端 | 小程序 `request` **只允许已备案的 HTTPS 域名**，`http://127.0.0.1` 在真机上不可能通 | **只在模拟器里验**，别花时间折腾真机 |
| 退出确认框的按钮是 `Cancel` / `OK`（英文） | 已知问题：`uni.showModal` 在 H5/小程序端不读我们传的按钮文案，按系统 locale 生成 | 已登记为体验改进，需要改用自绘弹窗。**不是本次验收的失败项** |
| 拍照/上传图片、分享、跳外部链接 点了没反应 | M2 只做登录注册；这些是 M3+ 的功能 | 本清单不覆盖它们 |
| 网盘链接点不开 | 个人主体小程序**不支持 `web-view`**，永远跳不了外部浏览器（ADR-0011 C1） | 设计约束，不是缺陷。M2 还没有这个功能 |

### 2.1 为什么用"IP 精确匹配"而不是路径前缀

`personal` 站点是 80 的 `default_server` 且**没有 `server_name`**。nginx 的选择顺序是「精确名 → 通配 → 默认服务器」，所以我们加 `server_name 8.138.237.212;` 之后：

- 用 **IP** 访问 → 精确匹配 → **我们的论坛**（`http://8.138.237.212/`，不带端口）；
- 用**域名**访问 → 不匹配 → 落到默认服务器 `personal`，**它的一切照旧**。

**`personal` 的配置一个字都没有改** ✓（部署脚本里也没有任何针对它的操作）。

### 2.2 顺带退休了 ssh 反向隧道

原先 OSS 回调要经「ECS nginx → `include` 到 `personal` 的某个路径 → ssh 反向隧道 → 开发机 8080」。现在回调地址直接是 `http://8.138.237.212/api/oss/callback`，它的 `Host` 就是 IP → 落到**我们自己的 server 块** → 反代到 `127.0.0.1:8080`。
**那条隧道连同它 2026-09-24 出过的 504 一起不用了**，`OSS_CALLBACK_URL` 也已改为公网地址。

## 5. 本次部署中修掉的两个自己造的 bug（值得记）

1. **`/opt/jdk-21` 软链放错位置**：脚本先 `mkdir -p /opt/jdk-21` 再 `ln -sfn <jdk> /opt/jdk-21` —— **`ln -sfn` 到已存在的目录会把链接放进目录里面**，于是 `/opt/jdk-21/bin/java` 不存在。教训：要么先删目录再建链，要么直接把链建在别处。
2. **备份脚本用了 `mysql` 而不是 `mysqldump`**：`mysql -uroot hy_forum | gzip` 里的 `mysql` 是**交互式客户端**，没 `-e`、也没输入重定向 → **它一直等 stdin 的 SQL** → 卡死 → 管道为空 → 备份文件**只有 20 字节**。
   **是靠"看文件大小"发现的**（20 字节 = gzip 空输入）。**如果只看"cron 装好了"，这就是一个永远不会备份的备份。**

**另有一处疏漏（当天发现并修复）**：导库时把 `view_count` / `like_count` / `collect_count` / `comment_count` **连同假数据一起带了过来**（例如帖子 `Hello` 显示 120 次浏览，是历次 E2E 测试刷的），用户第一眼就会看到。
处置：**计数一律按真实关系行重算**，`view_count` 归零（浏览量走 Redis，历史值无意义）。见 [`scripts/deploy/recount_fake_counters.sql`](../../scripts/deploy/recount_fake_counters.sql)。

## 7. 维护命令

```bash
ssh myserver "systemctl restart hy-forum"          # 重启后端
ssh myserver "systemctl status hy-forum"           # 状态
ssh myserver "tail -50 /var/log/hy-forum/app.log"  # 日志
ssh myserver "nginx -t && systemctl reload nginx"  # 改 nginx 后

# 备份
ssh myserver "/usr/local/bin/hy-forum-backup.sh"   # 立刻备份一次
ssh myserver "ls -lh /var/backups/hy-forum/"       # 看现有备份
scp myserver:/var/backups/hy-forum/*.sql.gz .      # 把数据带回本地

# 数据库口令（服务器上，600 权限）
ssh myserver "cat /root/.hyforum_db_pass"

# 上线新版本（本机构建 → 上传 → 重启；不要在服务器上构建）
cd server && mvn -DskipTests package
scp server/target/hy-forum-server-0.0.1-SNAPSHOT.jar myserver:/opt/hy-forum/app.jar
ssh myserver "systemctl restart hy-forum"
```

## 8. 回滚

```bash
# 后端回滚：换回上一版 jar 再重启
ssh myserver "cp /opt/hy-forum/app.jar /opt/hy-forum/app.jar.bak   # 先留档
               # 上传旧 jar 到 /opt/hy-forum/app.jar 后：
               systemctl restart hy-forum"
# 数据库回滚：从备份恢复
ssh myserver "zcat /var/backups/hy-forum/hy_forum-<日期>.sql.gz | mysql -uroot hy_forum"
```

## 审核建议关注点

> 2026-09-14 评审已对这 8 条**逐条作答**，并给出「3 处 P0 + 15 项 P1」的分级结论与处置：见 [`review/2026-09-14-方案评审记录.md`](review/2026-09-14-方案评审记录.md)。

1. ~~**部署双档位是否真的只有配置差异**~~ —— **已关闭（2026-09-14，D4 决策）**：档位机制**整体取消**，改为单一配置（[`adr/0010`](adr/0010-部署以本地开发为基准并取消档位.md)），该问题随之消失。
2. ~~**低配档位内存预算是否闭环**~~ —— **已降级为附录**：预算表已按**进程峰值**重算（v1.3 的「余量 320M」经查不存在，真实余量约 226M），但档位取消后该表转为 [`ops/deployment.md`](ops/deployment.md) **附录 A「应急参数集」**，仅当最终部署规格可用内存 < 4 GiB 时才启用。
3. **`sys_config` + `invite_code` 是否过度设计**：邀请制是备案受阻时的降级开关，需评估为它加两张表是否值得。
4. **`ContentAuditService` 抽象是否够用**：是否同时覆盖文本与图片；将来接入阿里云内容安全的替换成本。
5. **计数冗余字段的一致性策略**：同事务增减 + 校准任务是否足够。
6. **楼中楼两层约束**：`parent_id` + `root_id` 能否真正杜绝三层嵌套。
7. **合规义务可落地性**：论坛社区备案、公安备案、日志留存 ≥ 6 个月。
8. **与「已确认口径」的偏差**：见 [`PLAN.md`](PLAN.md) 第 2 节。

## 2. Sa-Token 到底承担了什么

### 2.1 结论：项目**没有**用 Sa-Token 的拦截器

已核实的"没有"（全仓库搜索）：

- 无 `SaInterceptor`、无 `SaServletFilter`、无 `SaTokenConfigure`；
- 无任何 `@SaCheckLogin` / `@SaCheckRole` / `@SaCheckPermission`；
- 无 `StpInterface` 实现（即**没有权限数据源**）；
- `pom.xml` 里**没有** `spring-boot-starter-security`，只引了 `spring-security-crypto` 取 BCrypt
  （[`../../server/pom.xml`](../../server/pom.xml) 第 99–103 行）。

Sa-Token 在本项目只做两件事：**① 登录态的存储与读写（Redis）；② 提供两个隔离的 `StpLogic` 实例**。
"拦截"是自写的 Spring MVC `HandlerInterceptor`。

### 2.2 拦截点与判定顺序

装配在 [`../../server/src/main/java/com/hyforum/common/web/WebMvcConfig.java`](../../server/src/main/java/com/hyforum/common/web/WebMvcConfig.java) 第 25–31 行：
只注册到 `/api/**`、`order(0)`。**不用"路径白名单"做免登录**，而是由注解在接口自己头上声明（fail-closed：
新写接口不加注解，默认就要登录）。

[`AuthInterceptor.java`](../../server/src/main/java/com/hyforum/common/web/AuthInterceptor.java) 的判定树：

| 顺序 | 条件 | 行为 | 读 token / 查库 |
|---|---|---|---|
| 0 | handler 不是 `HandlerMethod`（静态资源） | 放行（第 54 行） | 否 |
| 1 | `@OptionalLogin`（方法或类） | 尽力解析身份，失败也放行（第 58–61、105–123 行） | 有 token 才查 |
| 2 | `@AllowAnonymous`（方法或类） | 放行，**连 token 都不看**（第 62–64 行） | 否 |
| 3 | URI 以 `/api/admin` 开头 | `checkAdmin()`（第 67–68 行） | 是（admin 逻辑） |
| 4 | 其余 `/api/**` | `checkUser()`（第 69–71 行） | 是（user 逻辑） |

两个 check 都是**三步**（第 126–158 行）：① `checkLogin()` 失败 → 401；② `loginId == null` → 401；
③ `isUserActive()` / `isAdminActive()` 假 → 前台 **1004（并注销该 token）** / 后台 **403**。

第 ③ 步是**唯一每次请求都打数据库**的地方（`AccountStatusChecker` → `userMapper.selectById`），
换来的是「**封禁即时生效**，不用等 7 天 token 过期」。相关说明见
[`AccountStatusChecker.java`](../../server/src/main/java/com/hyforum/common/security/AccountStatusChecker.java)（含"为什么这个接口定义在 `common`"：铁律 3 禁止 `common` 依赖业务包）。

### 2.3 前后台隔离是怎么做出来的

[`StpUserUtil.java`](../../server/src/main/java/com/hyforum/common/security/StpUserUtil.java) 第 19 行与
[`StpAdminUtil.java`](../../server/src/main/java/com/hyforum/common/security/StpAdminUtil.java) 第 22 行各持有一个静态常量实例：

```java
public static final StpLogic STP = new StpLogic("user");   // 前台
public static final StpLogic STP = new StpLogic("admin");  // 后台
```

[`SaTokenLogicConfig.java`](../../server/src/main/java/com/hyforum/common/security/SaTokenLogicConfig.java) 第 19–23 行在 `@PostConstruct` 里
把两个实例登记进**项目自建的** [`StpLogicRegistry`](../../server/src/main/java/com/hyforum/common/security/StpLogicRegistry.java)（`register()` 同时写自己的静态表与 `SaManager.putStpLogic()`）。
为什么要多这一层（该类第 16–24 行）：**若两处各自 `new StpLogic("user")` 就会得到两个不同实例**，
行为上等价，但只要将来有人给其中一个设了 `setTokenStyle`/`setTokenName`，就会出现
"拦截器校验用的实例"与"登录用的实例"配置不一致的诡异故障。

效果：登录态 key 里带 `loginType`，**后台 token 打前台接口查不到 → 401，反之亦然**。
已有测试守着这个方向：[`M1RegisterModeTest.java`](../../server/src/test/java/com/hyforum/auth/M1RegisterModeTest.java) 第 177–199 行。

### 2.4 拒绝是怎么变成响应体的

拦截器**从不自己写响应**，一律抛 `BizException` → [`GlobalExceptionHandler`](../../server/src/main/java/com/hyforum/common/exception/GlobalExceptionHandler.java)
第 34–42 行翻译成契约体 `{code, message}` + 对应 HTTP 状态。理由写在 `AuthInterceptor` 类注释第 35–36 行：
两处拼装响应体必然漂移。注意 `GlobalExceptionHandler` 里**没有** `NotLoginException` 分支 ——
它已被拦截器就地捕获；真有漏网的会落到 `Exception` 兜底 → 500。

### 2.5 ⚠️ 只有"认证"，没有"授权"

- `admin.role`（`SUPER_ADMIN`/`ADMIN`）**唯一用途是在
  [`AdminAuthService.java`](../../server/src/main/java/com/hyforum/admin/service/AdminAuthService.java) 第 89 行原样返回给前端**，
  服务端没有任何一处按它判定。
- 后果：**任何有效的 admin token 都能调所有 `/api/admin/**`**。今天 `/api/admin` 只有 `login`/`logout`，
  风险为零；**M6 上审核/封禁/配置写接口前必须先补 RBAC**，否则 `ADMIN` 与 `SUPER_ADMIN` 无区别。
- 对应验收项状态：`M6_admin_apis_require_admin_token`、`SEC_admin_token_rejected_on_user_api`
  见 [`../testing/验收项-测试映射.md`](../testing/验收项-测试映射.md) 第 160、193 行，均为**待实现**。
- 横向越权（"这帖子是不是你的"）**不在拦截器里**，由业务层手写：
  `PostService.java:364-367,462`、`CommentService.java:263`（后者有测试 `SEC_cannot_delete_others_comment`）。

## 3. 每一次访问 URL 的完整拦截链路

### 3.1 时序

```
浏览器 / uni-app
   │  GET /api/user/me      Authorization: {token}（不带 Bearer）
   ▼
[Tomcat Servlet 容器]
   │  ├─ 项目自己**没有注册任何 Servlet Filter**（已核实：main/java 无 Filter 实现、
   │  │   无 FilterRegistrationBean；pom 无 spring-boot-starter-security）
   │  └─ Boot 自带过滤器 + Sa-Token starter 的上下文桥接：只把请求交给框架，**不做登录判定**
   ▼
[DispatcherServlet]
   ├─② HandlerMapping 找 handler
   │     ├─ 找不到 → NoHandlerFoundException → 404 统一响应体
   │     │            ⚠️ preHandle **不会执行**（见 §3.4-a）
   │     └─ 找到
   ├─③ AuthInterceptor.preHandle()   ← 唯一的鉴权点（判定树见 §2.2）
   │                                 成功 → CurrentUser.set(userId) [ThreadLocal]
   ├─④ Controller → Service（业务只从 CurrentUser 取 id，不碰 token）
   ├─⑤ afterCompletion() → CurrentUser.clear()（第 160–165 行）
   └─⑥ 任何异常 → GlobalExceptionHandler → {code, message} + HTTP 状态
```

### 3.2 token 从哪来、活多久

- 头名 = `application.yml` 第 80 行 `sa-token.token-name: Authorization`；前端
  [`web/src/utils/request.ts`](../../web/src/utils/request.ts) 第 165–169 行注入 `header.Authorization = token`，
  **不带 `Bearer`**（注释解释了加前缀会被解析成"带前缀的错误 token"，表现为"一直未登录"）。
- 登录态存 Redis；因为两套 `StpLogic`，**前台与后台的 key 不同**（含 `loginType`）。
- `timeout: 604800`（7 天）、`active-timeout: -1`（**明确关掉活跃度检查**：滚动浏览不会被踢出）。
  > 待核实：是否每次请求自动续签（`auto-renew`）本配置未显式设置，取决于框架默认值；
  > 本机 `.m2` 里没有 sa-token jar（不在默认仓库路径），本轮**未能核实**。

### 3.3 典型 URL × 实际结果

| 请求 | 走哪一支 | 结果 |
|---|---|---|
| `GET /api/boards` | `@AllowAnonymous` | 200，不看 token |
| `GET /api/posts`、`/api/posts/search`、`/api/posts/{id}` | `@OptionalLogin` | 未登录也 200；`liked`/`collected` 恒 false |
| `POST`/`PUT`/`DELETE /api/posts/**` | 不标注 → `checkUser()` | 匿名 401 |
| `GET /api/user/me` 匿名 | `checkUser()` | 401 |
| `GET /api/user/me` 带**后台** token | `checkUser()` | 401（两套逻辑） |
| `GET /api/users/{id}`、`/api/users/{id}/posts` | `@OptionalLogin` | 200，未登录时关注标志为 `null` |
| `GET /api/users/{id}/comments` | `@AllowAnonymous` | 200 |
| `GET /api/oss/signature` | 不标注 | 匿名 401（刻意：防匿名刷签名刷 OSS 流量） |
| `POST /api/admin/login` | `@AllowAnonymous` | 200（**不受注册模式影响**） |
| `POST /api/admin/logout` 带前台 token | `checkAdmin()` | 401 |
| 被封禁用户的 token → 任意受保护接口 | `checkUser()` 第③步 | **1004**，且 token 被注销 |
| `/actuator/health`、`/doc.html`、`/swagger-ui/**`、`/v3/api-docs` | **不进拦截器** | 200 |
| 任何不存在的路径 | **不进拦截器** | 404 统一响应体 |

### 3.4 拦截器的三个边界（回答"如何拦截"必须说清）

**(a) 它是"handler 闸门"，不是"URL 闸门"** —— 没有 handler 的路径走不到 `preHandle`。
所以 `/api/admin/stats`（不存在的端点）返回 404，**不会**触发后台登录态校验。这也是
[`M4OptionalLoginTest.java`](../../server/src/test/java/com/hyforum/common/M4OptionalLoginTest.java) 第 137 行那句断言空过的原因
（它接受 401/403/404，实际拿到 404）。M6 补后台接口时应顺手补一条**真实端点**的隔离测试。

**(b) 非 `/api/**` 完全不拦** —— 这是设计（`WebMvcConfig` 类注释：健康检查被 401 会让监控失效），
代价是"将来若有接口挂在 `/api` 之外，它默认是公开的"。目前所有业务端点都在 `/api/**` 下。

**(c) `/api/admin` 前缀判定用的是 `request.getRequestURI()`（含 context-path）**，而拦截器的路径匹配
用的是不含 context-path 的路径。现在没有配 `server.servlet.context-path`（已核实：全项目只有一份
`application.yml`，无任何 `context-path`）所以正确；**一旦有人加上，`/api/admin/**` 会被判成前台逻辑，
普通用户 token 就能过闸进入后台接口** —— "改一行配置就静默失守"，且无测试守着。
建议改用 `getServletPath()`，或让后台 Controller 打标记注解、拦截器按注解分发。

### 3.5 每次请求的固定开销

| 请求类型 | 读 Redis | 查 MySQL |
|---|---|---|
| `@AllowAnonymous` | 否 | 否 |
| `@OptionalLogin` 无 token | 否 | 否 |
| `@OptionalLogin` 带有效 token | 是 | 1 次点查（`user.status`） |
| 受保护的 `/api/**` | 是 | 1 次点查 |

> 若将来给 `AccountStatusChecker` 加缓存，**封禁就会变成"延迟生效"** —— 那里是"即时封禁"这条
> 不变量的唯一实现点，改之前必须意识到这一点。

### 3.6 客户端那一侧（uni-app）：没有全局路由守卫

- **页内判断、未登录不发请求**：如 `web/src/pages/collect/index.vue:14,95`、`web/src/pages/index/index.vue:71`。
- **请求层统一注入 + 401 处理**：`request.ts:135-275`；业务码非 0 且 `isAuthExpired` → `clearAuth()`
  （只清 token 与用户信息两个键，`web/src/utils/storage.ts:110-114`）。
- **只把 401 当"登录态失效"**：`web/src/utils/error-code.ts:82-91` 明确注释"不把 403 算进来 ——
  403 是已登录但无权限，此时清 token 会把用户无故踢下线"；各 API 文件按场景选 `clearAuthOn401`
  （登录接口设 `false`，密码错不该踢掉已有会话）。
- **操作前兜底**：`web/src/components/PostCard.vue:200-225` 的 `requireLogin()`。

## 4. hy-forum-server 目录结构（逐目录说明）

`hy-forum-server` = [`server/`](../../server) 这个 Maven 模块（`artifactId` 见 `server/pom.xml` 第 28 行）。
工程形态是**单 Maven 模块 + 分层 package**（不是多模块），口径见
[`../技术方案.md`](../技术方案.md) §3.3 v1.8 补充（第 151–164 行）。

### 4.1 顶层（只有 3 个文件 + 3 个目录）

| 路径 | 是什么 | 说明 |
|---|---|---|
| `server/pom.xml` | 模块定义 | 单模块工程；JDK 21 版本守门（`maven-enforcer`）、依赖树落盘（供铁律 7 的架构测试读）、Spring Boot 打包。注释里多处指向 `docs/技术方案.md` §3.1/§3.3 |
| `server/.jqwik-database` | jqwik 属性测试的数据库文件 | jqwik（`net.jqwik`）失败用例的复现种子记录（仓库根也有一份）。不是手写文件 |
| `server/target/` | **构建产物**（不入库） | `classes/`、`test-classes/`、`surefire-reports/`、`maven-archiver/`、`dependency-tree.txt`、可执行 jar。由 `.gitignore` 第 8–9 行的 `target/`、`**/target/` 忽略 |
| `server/src/main/` | 生产代码 | 见 4.2 |
| `server/src/test/` | 测试代码与测试配置 | 见 4.3 |

> 注：`docs/` 与 `pom.xml` 注释里若提到 `server/export_openapi.ps1`，**该文件当前不存在** ——
> 实际脚本在 [`scripts/export_openapi.ps1`](../../scripts/export_openapi.ps1)（属遗留引用，见 §5-⑦）。

### 4.2 `src/main/`

```

├─ java/com/hyforum/            ← 基础包，全项目唯一根（技术方案 §3.3：基础包名 com.hyforum）
```

| `common/config` | `CommonConfig`、`CaptchaProperties`、`RateLimitProperties`、`OpenApiConfig` | 跨模块配置属性与 Bean |
| `common/redis` | `RedisConfig`、`RateLimiter` | `StringRedisTemplate` 装配 + 限流器（`hy:rl:*`） |
| `common/oss` | `OssProperties`、`OssReadUrlSigner`、`OssThumbnailUrls`、`AvatarUrlSigner/Resolver`、`OssUrls` | OSS 的**共享抽象**（`post` 与 `media` 都要用；密钥不放这里，最小暴露） |
| `common/audit` | `SensitiveTextChecker` | 敏感词能力的抽象接口（实现由 `audit` 模块提供） |
| `common/notify` | `NotificationPublisher`、`NotificationType` | 通知发布能力的抽象接口（实现由 `notify` 模块提供） |

> `common/audit` 与 `common/notify` 的存在揭示了一条**本项目的协作范式**：
> 业务模块之间的能力通过"**`common` 里放接口 + 由某业务模块实现**"来传递，
> 这样既满足铁律 3（业务包之间禁止互相依赖），又不把基础设施焊死在业务实现上
> （`AccountStatusChecker` 是同一个套路的第一个例子）。

#### `domain/` —— 实体与 Mapper（10 个子域）

每个子域都是 `entity/` + `mapper/` 两件套（`user` 额外有 `vo/UserVO`）：

| 子域 | 对应表（见 [`../db/schema.sql`](../db/schema.sql)） |
|---|---|
| `domain/user` | `user`（+ `vo/UserVO`：跨模块共享的用户视图） |
| `domain/admin` | `admin` |
| `domain/board` | `board` |
| `domain/post` | `post`、`post_image` |
| `domain/interaction` | `comment`、`post_like`、`comment_like`、`post_collect`、`user_follow` |
| `domain/notify` | `notification` |
| `domain/report` | `report` |
| `domain/sensitiveword` | `sensitive_word` |
| `domain/invite` | `invite_code` |
| `domain/config` | `sys_config`（+ `admin_operation_log` 归 `domain/admin`） |

**为什么实体/Mapper 不放在各自的业务包里**：铁律 3 只允许业务包依赖 `common` 与 `domain`，
而 `post` 要读 `user`、`interaction` 要读 `post` —— 若实体各自归属业务包，这些读取就成了跨模块调用。
统一收进 `domain` 后，"读实体"是合法操作，"调别人的 Service"才违规（`ArchitectureRulesTest` 第 69–73 行的注释
专门记了这次踩坑：**即使依赖发生在 controller 层也算违规**）。

#### 业务包（8 个）—— 每个包 = 一个"模块"、一个 Agent 的所有权单位

| 业务包 | 职责 | 子包结构（实测） |
|---|---|---|
| `auth` | 注册 / 登录 / 登出 / 图形验证码 / 注册模式 | `captcha/`（验证码实现）、`mode/`（open·invite·closed）、`validation/`（密码强度等校验器）、`controller/`、`service/`、`dto/`、`vo/` |
| `post` | 版块与帖子 | `disk/`（网盘链接归一化：`DiskFieldNormalizer`、`DiskType`、`DiskFields`、`DiskCopyText`，ADR-0008）、`config/`（`PostProperties`、`PostScheduleConfig`）、`controller/`、`service/`、`dto/`、`vo/` |
| `interaction` | 评论 / 点赞 / 收藏 / 关注 / 首页流 | `controller/`、`service/`、`dto/`、`vo/` |
| `user` | 面向**他人**的用户接口（个人主页、他的帖子/评论、我的收藏、资料） | `controller/`、`service/`、`dto/`、`vo/` |
| `media` | OSS 直传签名与上传回调 | `controller/`、`service/`、`oss/`（验签：`RsaOssCallbackVerifier`、`OssPublicKeyProvider`）、`config/`（`OssCredentialProperties` 等，**密钥只在这里**）、`vo/` |
| `audit` | 敏感词、审核队列、举报 | `controller/`、`service/`、`dto/`、`vo/` |
| `notify` | 消息通知 | `controller/`、`service/`、`vo/` |
| `admin` | 管理后台接口与留痕 | `controller/`、`service/`、`vo/`（目前只有 `login`/`logout`，其余归 M6） |

每个业务包根下都有一个 **`PackageMarker.java`**（`post`/`media`/`interaction`/`notify` 已实测存在）：
纯声明类，作用是**让空包真实存在于编译产物里**，否则 ArchUnit 规则会"通过但什么都没检查"（假绿）。
它被单独声明为可被所有业务包依赖的叶子层，见 `ArchitectureRulesTest.java:50-57`。

> 历史注记：`post/config/OssProperties.java` 已按 M3b 裁决迁到 `common/oss/`（`post` 只留 `PostProperties`/`PostScheduleConfig`）。

| `application.yml` | **唯一**运行配置：端口、数据源、Redis、MyBatis-Plus、Sa-Token（第 79–88 行）、业务开关、springdoc、OSS（密钥走环境变量占位）。第 4–8 行写明"禁止硬编码密钥"（铁律 5）与 ADR-0010「单一配置、无档位」 |

### 4.4 一句话记住这个结构

```
com.hyforum
├─ common    = 横向基础设施（所有模块都能用）
├─ domain    = 共享数据层（实体 + Mapper，按业务域分子目录）
└─ <业务包>   = 纵向切片（auth/post/interaction/user/media/audit/notify/admin）
               每个切片自带 controller/service/dto/vo，切片之间**禁止互相调用**
```

## 5. 本轮发现的缺口 / 风险（按严重度）

| # | 事项 | 证据 | 影响 |
|---|---|---|---|
| ① | **只有认证没有授权**：`admin.role` 无服务端校验 | `AdminAuthService.java:89`；全仓库无 `@SaCheckRole`/`StpInterface` | M6 上后台写接口前必须补，否则 ADMIN 与 SUPER_ADMIN 无区别 |
| ② | **`/api/admin` 前缀判定用 `getRequestURI()`（含 context-path）** | `AuthInterceptor.java:66-67`；当前无 `context-path` | 一旦有人加 context-path，后台接口会被判成前台逻辑 → 普通用户 token 可过闸（潜在越权，无测试守着） |
| ③ | **文档写了"登录失败锁定 15 分钟"，代码里没有** | `../技术方案.md` §9 第 886 行；全仓库无失败计数/lockout；`../review/2026-09-14-方案评审记录.md` 第 118 行 **P1-9 未结案** | 有意未结案（按账号锁会被用于账号 DoS），但文档那行会让人以为已实现 |
| ④ | **前后台隔离有一个方向没被有效测到** | `M4OptionalLoginTest.java:137` 打的是不存在的 `/api/admin/stats` → 实拿 404，断言里 `isIn(401,403,404)` 空过 | 前台 token → 后台接口 这条路径缺真实端点的测试 |
| ⑤ | **Redis 登录态键名：文档与实际不一致，测试清理很可能是空操作** | 文档 `../技术方案.md` §7 第 743 行写 `hy:token:*`；M2 实测 `KEYS *` 是 `Authorization:user:token:{uuid}`（`tests/verify/w4-m2/报告.md:211-215`）；而 `M3ApiTestSupport.java:107-110`、`M4ApiTestSupport.java:142-145,172` 按 `hy:token:*` 删键 | **推断（未实测）**：这些 `@AfterEach` 登录态清理没删到东西 —— 而 M3 的注释说它正是用来防"清表重置自增 id → 旧 token 映射到新用户"的越权假象 |
| ⑥ | **ArchUnit 的"七个业务包"清单**没有 `com.hyforum.user` | `ArchitectureRulesTest.java:41-48` vs 实际存在的 `com.hyforum/user/**` | 铁律 3 对 `user` 包**不生效**：它今天若依赖了别的业务包，测试不会红 |
| ⑦ | `docs`/`pom.xml` 里引用的 `server/export_openapi.ps1` 不存在 | 实测 `server/` 下只有 `pom.xml` 与 `.jqwik-database`；脚本在 `scripts/export_openapi.ps1` | 遗留引用，照文档找脚本会找不到 |
| ⑧ | `seed.sql` 声明"明文不在仓库里"，但 `交接说明.md:60` 有明文 | §1.2 | 口令进过 git 历史；改文档不改变历史，应换口令 |
| ⑨ | `CurrentUser` 的不变量靠"抛异常的先后顺序"保证 | `AuthInterceptor.java:163-164` 注释说"必须清理"，但 `preHandle` 抛异常时该拦截器的 `afterCompletion` **不会被调用**；现在不泄漏是因为所有拒绝路径都在 `CurrentUser.set()` **之前**抛 | 谁把 `set()` 提前一行就成了跨请求身份串号；这类改动不会让任何现有用例变红。建议加一条断言 |

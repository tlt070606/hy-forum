## 覆盖缺口检查（自动化）

写一个脚本，对比本表与测试方法名，输出「哪些验收项没有对应测试」：

```bash
# 伪代码
grep -oE '`[A-Z][A-Za-z0-9_]+`' docs/testing/验收项-测试映射.md | sort -u  > /tmp/expected.txt
grep -rhoE 'void [A-Z][A-Za-z0-9_]+\(' server/src/test admin/src/test | ...   > /tmp/actual.txt
diff /tmp/expected.txt /tmp/actual.txt
```

> 这比代码覆盖率有意义：覆盖率 90% 也可能一条业务规则都没验证过。

> ⚠️ **这个检查有已知盲区（2026-09-16 实测）**：脚本只扫 `server/src/test` 下
> **Java 方法名**形式的用例（`void <Name>(`）。于是：
> · `web/e2e/**` 的 Playwright 用例（M2 的 3 条）与 `tests/golden-path/**` 的黄金路径
>   **它看不到**，会**永久显示为"缺口"** —— 那是**假缺口**，不是漏测；
> · `admin/src/test` 也标着"目录不存在"。
> 结论：**断言口径是「已实现数 + 缺口数 ≠ 全绿即代表漏测」是不成立的**，读数字时先看这一条。
> 修它属测试基建的后续工作，**不要**为了让数字好看而把行删掉 —— 那才是真的漏测。

# 验收项 → 测试映射表

> **用途**：防止漏测。每条验收标准都必须有对应的测试方法名。
> **来源**：验收标准只来自 [`../PLAN.md`](../PLAN.md) §4、[`../技术方案.md`](../技术方案.md) §8／§9／§10、[`../adr/`](../adr/)。
> 本表**只做映射**，不新增、不修改验收标准 —— 若发现验收标准本身有问题，去改 PLAN，不要在这里改。
> 策略与纪律见 [`README.md`](README.md)。

**状态取值**：`待实现` / `已实现` / `已验证`（已验证 = 通过变异测试证明其有效）
**层次**：`结构` / `单元` / `集成` / `E2E` / `手工`

> ⚠️ 标 **[阻塞]** 的条目依赖尚未决定的 P1 项，**在对应 P1 结案前不要写这些测试**（写出来也要返工）：
> **P1-6** 计数回退与校准任务定义 · **P1-7** 限流阈值 · **P1-9** 登录失败锁定粒度。
>
> ✅ 已结案：**P1-3**（楼中楼语义，2026-09-14 定案为归并语义 (a)）、**P1-4**（邀请码并发，定案为条件更新 + 影响行数校验）—— 相关测试已解锁。

> **CR-001 裁决（L1，2026-09-14）**：这些测试不来自验收标准，而是**基建自身的自检**。
> 不登记的话，覆盖率脚本每次都会把它们列为「多余」—— 真出现多余测试时就会被淹没。
> **它们不是装饰**：基建失效会让后面所有模块的测试一起变成"假通过"，所以必须自证。

| 项 | 来源 | 测试方法名 | 断言要点 | 层次 | 状态 |
|---|---|---|---|---|---|
| 测试库连通与基线 | 基建自检 | `INFRA_connected_to_test_database` | `SELECT DATABASE()` = `hy_forum_test`；表数 = 16；MySQL ≥ 8.0.16 | 集成 | **已实现** |
| Redis 连通与 TTL | 基建自检 | `INFRA_connected_to_redis_and_ttl_works` | 对 VM Redis（`192.168.100.128:6380`）SET / GET 成功且 TTL 生效 | 集成 | **已实现** |
| 清表工具的破坏性防线 | 基建自检 | `INFRA_table_cleaner_refuses_non_test_database` | 传入**非测试库名**必须抛异常 —— **防线不能只写在注释里** | 集成 | **已实现** |
| schema 基线 | 基建自检 | `INFRA_schema_baseline_respected` | 外键数 = 0；全部 InnoDB + utf8mb4 | 结构 | **已实现** |
| 并发幂等样板 | 基建样板（M4–M6 照抄） | `SAMPLE_idempotency_concurrent_unique_index` | 20 线程并发插入同一 `(post_id,user_id)` → 表内行数 = 1；成功数 = 1；`DuplicateKeyException` 计数 = 19；`readyThreads()` = 20（**自证真并发**，防"串行跑了 20 次"） | 集成 | **已实现** |
| 两层结构 CHECK（双向） | ADR-0009 / P1-3 | `SCHEMA_check_constraint_rejects_violation` | ① 合法主楼 `(0,0)` 与楼中楼 `(x,x)` **写入成功**；② 三种非法组合**必须失败**，且错误码为 **MySQL 3819** + 约束名 `chk_comment_two_levels`；③ 被拒的写入不留痕 | 集成 | **已实现** |

> **为什么 `SCHEMA_check_constraint_rejects_violation` 必须是双向的**：只测"拒绝"是不够的 —— 把约束写成 `CHECK (1 = 0)` 同样能通过"拒绝测试"，却会让所有合法评论写入失败。**实测已证明**：把约束改成"只放行楼中楼、漏掉主楼"时，三种非法组合仍全部被拒（`3819`），**只测拒绝的测试会全绿**，是本测试靠"合法行必须写入成功"抓到的。
>
> 这与 M0 段那条「schema 一次执行成功」（由 `scripts/verify_m0.ps1` 执行）不是重复：前者是 **CI 每次自动跑的守护**，后者是**建库时的一次性真机验收**。
>
> **维护提醒**：本节的条目名会被 `check_test_coverage_gaps.ps1` 当测试方法名提取，所以**正文里不要用反引号包裹看起来像测试方法名的字符串**，否则会被误算成一条期望条目。


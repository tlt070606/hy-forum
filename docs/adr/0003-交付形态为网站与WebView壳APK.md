# ADR-0003：交付形态为网站 + WebView 壳 APK，不做微信小程序

- 状态：已接受，**已于 2026-09-14 修订**（交付形态由两端扩为三端；安卓打包方式改变）
- 日期：2026-09-14
- 修订依据：[ADR-0011 前端改用 uni-app 作为唯一前端](0011-前端改用uni-app作为唯一前端.md)

## 背景

需求方最初要求「小程序 + 网页 + 安卓」三端，后明确放弃小程序。

## 决策

- **主形态**：网站（Vue 3 SPA + PWA）
- **安卓端**：Android WebView 壳，加载线上站点地址
- **不做**：微信小程序

## 理由

1. 网站主体为**个人主体**，无法开通阿里云短信服务与微信开放平台网站登录，做小程序也会卡在类目与内容审核上。
2. 交付形态收敛为两种后，前端可完全使用 Web 栈，不再迁就小程序组件与 API 限制。
3. PWA 可让用户「添加到主屏幕」，以接近零的成本获得 App 般的使用体验。

## 后果

- WebView 壳需额外实现：拦截网盘域名并交给系统浏览器 / 对应 App、处理物理返回键、启动页避免白屏。
- 加载的是 HTTPS 站点，**无需**开启 `usesCleartextTraffic`；调试期若用 HTTP 需临时开启并在上线前关闭。
- 壳工程中不得硬编码任何密钥或接口凭证（APK 可被反编译）。

## 修订（2026-09-14）：交付形态由两端扩为三端

需求方改为要增加微信小程序端（练习用、不上线），并指定 uni-app 为唯一前端。本节取代上面的「决策」与「后果」，其余部分保留为历史记录。

**新的交付形态**：

| 端 | 形态 | 打包方式 | 定位 |
|---|---|---|---|
| 网站 | H5（uni-app 编译） | 静态产物 + Nginx | 主形态 |
| 安卓端 | App（uni-app 编译） | uni-app 打安卓包 | 主形态 |
| 微信小程序 | 小程序（uni-app 编译） | 微信开发者工具上传 | **仅练习，不上线** |

**改动要点**：

1. **不做微信小程序 → 改为：做，但仅用于练习**。个人主体小程序有两条硬约束使它在可预见的将来无法上线，需求方已知并接受：不支持 `web-view` 组件、`request` 只允许已备案 HTTPS 域名（详见 ADR-0011 的 C1/C2/C4）。
2. **安卓端不再需要 Kotlin WebView 壳**：uni-app 直接打包安卓，`PLAN.md` 的 **M7 整块工作删除**。因此上面「后果」里那三条关于 WebView 壳的要求（拦截网盘域名、返回键、壳内不得放密钥）**随之作废** —— 但**最后一条的精神仍然有效且必须遵守**：**打成包的前端代码同样可被反编译，绝不能包含 AccessKey 或 AppSecret**（铁律 5、8）。
3. **PWA 是否保留待定**：H5 由 uni-app 产出，仍可配 manifest，但优先级下降；`PLAN.md` 交付清单里保留但标注为次要。
4. 理由 1（个人主体做小程序会卡在类目）**并未失效** —— 它正是 C4 的来源，也是"小程序只做练习"这一决策的依据。

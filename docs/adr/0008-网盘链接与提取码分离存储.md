# ADR-0008：网盘链接与提取码分离存储，并在写入时归一化

- 状态：已接受
- 日期：2026-09-14

## 背景

需求方曾质疑「网盘链接不就已经包含提取码了吗，为什么还要单独一个字段」。
实际调研结论如下：

| 网盘 | 链接形态 | 是否含提取码 |
|---|---|---|
| 百度网盘 | `https://pan.baidu.com/s/1aBcDeFgHiJ` | 默认不含；分享者开启后可带 `?pwd=abcd` |
| 阿里云盘 | `https://www.alipan.com/s/xxxx` | **无提取码机制** |
| 夸克网盘 | `https://pan.quark.cn/s/xxxx` | **无提取码机制** |
| 115 / 天翼 / 迅雷 | `https://115.com/s/xxxx` 等 | 有独立访问码 |

即：提取码**不能**从链接中可靠推出。

## 决策

`post` 表使用两个独立字段：

- `disk_url` —— 干净的分享链接（不含 `pwd` 参数）
- `disk_code` —— 提取码，**可为空**

写入时执行**归一化**：若 `disk_url` 携带 `pwd=` 查询参数，则正则解析出提取码写入 `disk_code`，并将 `disk_url` 规范化为不含参数的干净链接，两者始终保持一致。

前端渲染：

- `disk_code` 非空 → 渲染「链接 + 提取码 + 一键复制整段」卡片
- `disk_code` 为空 → 仅渲染「打开链接」按钮

## 理由

1. 阿里云盘与夸克无提取码机制，字段必须允许为空，否则这两类分享无法录入。
2. 用户从网盘 App 复制的链接通常不含 `pwd` 参数，提取码是另行显示的，分开填写更符合实际录入习惯。
3. 分开存储使前端能渲染出结构化的复制卡片，而不需要反向解析 URL。

## 后果

- 需实现归一化解析，并为其编写单元测试（覆盖带 `pwd` / 不带 `pwd` / 提取码为空三类情况）。
- 一键复制的内容格式为：链接一行、提取码一行、来源一行。
- Web 端无法直接跳转网盘 App，需在 UI 上给出明确的引导文案。

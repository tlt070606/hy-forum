# ADR-0011：前端改用 uni-app 作为唯一前端（H5 + 微信小程序 + 安卓）

- 状态：已接受
- 日期：2026-09-14
- 取代：[ADR-0002 前端采用 Vue 3 + Vite + Vant，而非 uni-app](0002-前端采用Vue3与Vite与Vant.md)
- 修订：[ADR-0003 交付形态](0003-交付形态为网站与WebView壳APK.md)（交付形态由两端扩为三端；删除 Kotlin WebView 壳）

## 背景

ADR-0002 选择纯 Web 栈（Vue 3 + Vite + Vant），其前提写得很明确：**「项目已明确不做微信小程序」，因此 uni-app 只剩「原生 App 打包」这一个优势。**

2026-09-14 需求方改变口径：

- 要**增加微信小程序端，用于练习开发**（**不上线**）；
- **uni-app 作为唯一前端**（不是叠加第二条线）；
- **也出 H5**；
- 安卓端**改用 uni-app 打包**，删除原计划的 Kotlin WebView 壳。

前提消失，原决策随之失效。

## 决策

1. 前端技术栈改为 **uni-app（Vue 3 + Vite + TypeScript）**，作为**唯一前端代码库**。
2. 编译目标三个：**H5（网站）**、**微信小程序**、**安卓 App**。
3. UI 组件库由 Vant 4 改为 **wot-design-uni**（Vue 3 + TS 支持好）。Vant 4 无法用于小程序端（见 C3）。
4. **删除** ADR-0003 规划的 Kotlin WebView 壳工程，以及 `PLAN.md` 的 **M7 整块工作**。
5. **小程序端继续使用「用户名 + 密码 + 图形验证码」登录，不接入微信授权登录。** 理由：① 不引入 OpenID / UnionID 体系，**数据库与后端零改动**；② 与已确认口径（用户名+密码、不用短信）一致；③ 避免小程序用户与网站用户分裂成两套账号，也避免 AppSecret 的保管问题（铁律 5）。
6. 由 5 推出一个重要结论：**本次变更是纯前端变更，后端一行不改。**

## 关键约束（必须先说清，否则会有人以为"顺手就能上线"）

| # | 约束 | 后果 |
|---|---|---|
| **C1** | **个人主体小程序不支持 `web-view` 组件** | 不能像 APK 那样套站点；小程序页面**必须真写** |
| **C2** | 小程序 `request` 只允许**已备案的 HTTPS 域名** | 本地后端只能靠微信开发者工具的「不校验合法域名」开关连通。因此该小程序**只能停在开发者工具与真机预览**；体验版即受限，正式版走不通。**需求方已知并接受**（这是"练习"定位的必然结果，不是意外） |
| **C3** | **Vant 4 不能用于小程序**（小程序无 DOM，Vant 是 Web 组件库） | UI 库必须换（决策 3） |
| **C4** | 个人主体小程序的类目不允许「论坛 / 社区」 | 即使将来想上线也上不了；与"不上线"的定位一致，但**不要指望它日后能直接发出去** |

> C2 与 C4 合起来的意思是：**这一端永远是练习端。** 把它当"将来能上线的产品"来投入会浪费精力。

## 理由（为什么这次推翻 ADR-0002 是对的）

1. **原来的前提没了。** ADR-0002 的核心理由是"不做小程序 → uni-app 只剩原生 App 打包这一个优势"。现在要做小程序，这个"用不上的优势"变成了**唯一能满足需求的选型**，理由链整条反转。
2. **一套代码编三端，优于维护两套。** 需求方已明确 uni-app 为唯一前端，因此不存在"Web 栈 + 小程序两套代码"的重复维护。
3. **顺带收益：安卓端不再需要 Kotlin 壳。** M7 整块工作消失，少维护一个工程，也不再需要处理 WebView 的返回键与链接拦截。
4. **ADR-0002 最看重的"热更新"担忧并未恶化。** H5 与小程序都不需要用户重装；安卓 App 原本用 WebView 壳加载线上站点，其实也是热更新。所以该理由**不构成反对**（注意：uni-app 打包的原生 App 若要真正热更新，需另配 wgt 资源包方案，本期不做）。

## 后果（代价必须承认）

- **H5 端的组件生态弱于 Vant。** wot-design-uni 在 H5 的成熟度与社区资料不如 Vant 4。这是为小程序端付的代价。
- **需要条件编译**（`#ifdef MP-WEIXIN` 等）处理平台差异：本地存储、图片上传、返回键、分享。条件编译写多了会让代码难读，应集中封装而不是散落各处。
- **H5 产物仍是 SPA**，`PLAN.md` R11（SPA 不利 SEO）风险不变。
- 开发小程序需要**微信开发者工具**与一个 AppID —— 可用**小程序测试号**，无需注册主体（与 C2 配套：反正只在本机调试）。
- 小程序端功能**对齐网站全部功能**（需求方决定），所以 M2–M6 的前端工作量比原计划大。但这是"多做一个端"，**不是"重做一遍"**：后端接口与数据模型完全复用。
- 团队对 uni-app 的调试经验少于纯 Vite，遇到问题可参考的资料更多是中文社区而非官方英文文档。

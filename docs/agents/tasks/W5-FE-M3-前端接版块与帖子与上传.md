## 3. 禁止（违反即返工）

1. **禁止手写 OSS 表单字段**。`policy`／`signature`／`dir`／`callback`／`expire`／
   （CR-F 之后的）`accessKeyId` **一律来自 `GET /api/oss/signature` 的响应**，
   前端只做"原样填入表单 + POST 到 `host`"。
2. **禁止在任何被 git 跟踪的文件里写 AccessKey Secret**（铁律 5）。前端**只允许使用服务端签名**。
   拿到的 `accessKeyId` 是**请求时临时收到的标识**，不是配置项 —— **不要把它写进 `.env` 或常量**。
3. **禁止用 Vue Router / Axios / Vant**：uni-app 下路由用 `pages.json`、请求用 `uni.request` 封装、
   UI 库是 **wot-design-uni**（见 [`../../adr/0011`](../../adr/0011-前端改用uni-app作为唯一前端.md)）。
4. **禁止散落 `#ifdef`**：平台差异只有三处（本地存储、请求、跳转外部链接），**集中封装**。
5. **禁止把 `Record<string, any>` 当答案**：契约里字段是具名的就用具名类型。
6. **禁止为了省事新装依赖**：先看 `web/node_modules` 里有没有（`vue`/`pinia`/`wot-design-uni` 都有）。
   真需要新依赖 → 在报告里说明理由。
7. **禁止改弱测试来变绿**（删断言、放宽等值、`@ts-ignore`、`as any`、把文件从 `tsconfig.include` 里删掉）。
   **"拆开检查"是对的，"关掉检查"是错的。**

## 5. L1 已答完的口径（**照办，不要再来问**）

这些是"换一种读法就换一种对外行为"的问题，**L1 已经定完**（后端那一段为此多花了一小时，
因为当时的规定是"必须问 L1"）。本任务书直接把答案给你：

| # | 口径 | 值 |
|---|---|---|
| 1 | 统一响应体 | `{code, message, data}`；`code=0` 才是成功 |
| 2 | **错误码 → 文案** | 以 `技术方案.md` §6.1 的表为准。**必须按码分支**，不能只判断"失败了" —— 报错报错码比不报错更坏 |
| 3 | **发帖限流** | `2002 发帖过于频繁` 走 **HTTP 200** + 业务码（不是 429）。前端**按业务码处理**，`message` 里已带重试秒数 |
| 4 | **401 处理** | 未登录/失效 → 跳登录页；**不得把 401 当成成功**、不得白屏 |
| 5 | 分页硬上限 | 列表 `size` 后端硬上限 **20**（传 100 也只给 20），前端不要假设拿到 100 |
| 6 | 列表字段 | 列表**只返回摘要**（无正文）；列表图用 `thumbUrl`（缩略图），**不要用原图** |
| 7 | 详情页图片 | 只展示后端返回的 `images`（后端已过滤 `audit_status=2`）；**前端不得自己拼图片 URL** |
| 8 | 一键复制 | 文案格式见 §5.5，由后端 `DiskCopyText` 锁定；前端只负责复制。**小程序端只能复制、跳不了外部浏览器** |
| 9 | **资源版块判断** | 用 `GET /api/boards` 返回的 **`isResource`** 决定发帖表单是否显示网盘字段。**字段名逐字是 `isResource`** |
| 10 | 网盘字段 | 资源版块必填 `diskType` + `diskUrl`，`diskCode`（提取码）可空 |
| 11 | 编辑语义 | `PUT` 是**覆盖**：**没传的字段视为清空**（资源版块改帖必须带上网盘字段） |
| 12 | 上传表单 | 字段与形态**全部来自 `GET /api/oss/signature`**；`callback` 是**Base64 的回调配置字符串**，**原样填入**，不要自己拼 JSON |

## 6. 完成定义（DoD）

### 6.1 最小闭环优先（**硬要求，先做这个**）

**先让这条端到端跑通，再补其它页面**：

> 在 H5 上：**选一张图 → 上传到 OSS（直传）→ OSS 回调落库 → 发帖 → 详情页看到这张图**

**为什么**：这条一旦通，"M3 的验收能不能达成"就有答案了；而其它页面写得再全，这条不通就一分验收都拿不到。
**不要**先把五个页面都写完再第一次跑端到端 —— 那样你会在最后一刻才发现跨模块问题。

### 6.2 页面清单（最小闭环之后按此顺序补）

| # | 页面 | 依赖端点 | 关键点 |
|---|---|---|---|
| 1 | 版块列表（首页） | `GET /api/boards` | 用 `isResource` 标记资源版块 |
| 2 | 帖子列表 | `GET /api/posts`（`boardId`/`sort`/`page`/`size`） | `sort=latest\|hot\|essence`；摘要 + `thumbUrl` |
| 3 | 帖子搜索 | `GET /api/posts/search`（`keyword` 必填） | 缺 `keyword` 是 400 |
| 4 | 帖子详情 | `GET /api/posts/{id}` | 图片九宫格、网盘信息、**一键复制**；404 要给友好页而不是白屏 |
| 5 | 发帖 | `GET /api/oss/signature` + `POST /api/posts` | 资源版块显示网盘字段；≤9 张图 |
| 6 | 编辑 / 删除 | `PUT`／`DELETE /api/posts/{id}` | 仅作者；编辑后 `status` 回 0（前端要提示"重新进入审核"） |

### 6.3 必交证据（缺一条就算没完成）

1. **最小闭环的实跑证据**：截图**不算**，要 **HTTP 请求/响应 + `post_image` 的 SQL 输出**
   （`mysql -u root -p1234 -D hy_forum -e "SELECT ..."`）。
2. **`npm run type-check` exit 0**（贴输出）。它此前**从未通过**过 12 个类型错误，修完必须保持绿。
3. **H5 端到端**（你自己的 Playwright，`web/e2e/**`）：至少覆盖
   ① 列表 → 详情 →（登录后）发帖成功 ② 未登录访问受保护动作 → 跳登录。
   要求「红 → 绿」两次输出（**先写测试跑出失败，再实现跑通**）。
4. **反向验证至少 2 条**：证明你的检查**会失败**。推荐：
   ① 把 API 基址改成一个错误端口 → 相关用例必须变红；
   ② 把 `isResource` 判断写反 → "资源版块显示网盘字段"必须变红。
   **一个从未失败过的检查不能证明它在检查任何东西。**
5. **`git status --short` + 逐文件改动清单**（对照 §2 逐个说明）。
6. 报告里**逐条说明**：§6.2 六个页面哪些做完、哪些没做、没做的**为什么**。
   **没验证就写没验证** —— 本项目的验收只认命令输出，不认"基本上做完了"。

## 8. 做事节奏（**硬约束，都是踩出来的**）

### 8.1 只有三类事允许"停下等人"

1. 要改**契约**（`openapi.json`／`schema.sql`）；
2. 要改**铁律 / ADR**；
3. 要动**别人写权清单里的文件**。

**其余一切**（某个字段怎么显示、错误文案怎么写、间距多少、某个交互用哪种组件）——
**写成"我采用的读法 + 理由"继续做**，把它留在心跳文件与报告里，由 L1 **事后**审。
探索期往前走的风险（可能返工一处）远小于停住的风险（停一小时）。

### 8.2 进度心跳（**硬要求**）

**每轮结束（或每 ~20 步）往 `.tmp/progress-W5-FE-M3.md` 追加一行**：

```
2026-09-16 22:10 | 版块列表 + 帖子列表已接完，H5 可看到真实数据 | 下一步：详情页 | 待裁：无
```

一行 append 的成本，换来"外面随时能看见你在干什么"，并且**心跳超 15 分钟没更新 = 真卡了**。
不用维护格式，追加即可。

### 8.3 单轮上限

**单轮 ≈70 步**或**单个工具调用 ≈10 分钟**，先到为准 → **停下交付一次**（已完成什么／下一步／卡在哪）。
**每完成一个可编译的单元就落盘**，不要攒到最后一次性写。
上一轮有个 agent 跑出 **1 个 turn、127 步、工具调用 45 分钟**，需求方在外面看着像卡死，
**按了中断**，把一个跑到一半的验证掐断了。**分段可见比一次性交付安全。**

### 8.4 提交

- `git commit` 用 Conventional Commits，例如 `feat(web): 版块与帖子列表接入真实接口`。
- **不要 `git push`**（L1 复核后统一推送）。
- **不要 `git commit --amend`**（L1 可能已在你之上提交了别的东西）。

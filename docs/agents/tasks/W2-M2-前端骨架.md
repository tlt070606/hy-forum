## 5. 完成定义（DoD）—— 必须贴出真实命令输出

### 第 0 步（**先做这个，它决定后面能不能做**）：验证工具链

在写任何业务代码之前，先确认 uni-app CLI 在本机可用：

1. 用 uni-app 官方 CLI 模板创建工程到 `web/`
2. `npm install` 成功
3. `npm run build:h5` 成功，产出 H5 产物
4. `npm run build:mp-weixin` 成功，产出小程序产物

**若 Node 26 导致任何一步失败**：不要硬扛、不要降级 Node（那是需求方的环境决策）。按 §6 报 `BLOCKED`，写清**失败在哪一步、报错原文、你判断的根因、可选方案**。

### 1. 工程骨架

- uni-app + Vue3 + Vite + TS + **wot-design-uni** + Pinia
- 页面路由用 **uni-app 的 `pages.json`**（小程序端没有 Vue Router）
- **平台差异必须集中封装**，不能散落各处：本地存储、请求、剪贴板、分享各自一个模块，内部用 `#ifdef MP-WEIXIN` 等条件编译

### 2. 请求层与契约一致性

- 自己封装 `uni.request`（**小程序端不能用 Axios**），统一处理：`Authorization` 头、统一响应体 `{code,message,data}`、错误码到提示的映射
- **逐条对照 `openapi.json` 的 8 个路径**，把 `docs/技术方案.md` §6.1 的错误码映射成用户可读文案
- 前端类型**从 `openapi.json` 生成**（`openapi-typescript` 之类），生成物放 `web/src/api/generated/` —— 该目录**由 L1 独占，你不要手改生成物**，只运行生成命令

### 3. 登录注册页（对齐契约）

- 注册：用户名 + 密码 + 昵称 + **图形验证码** + 勾选协议（契约要求 `agreeProtocol` 必填）
- 登录：用户名 + 密码
- 图形验证码：`GET /api/auth/captcha` 返回 `{uuid, base64Image}`；小程序端 `image` 支持 base64，**两端同一套代码**
- **注册模式动态渲染**：先 `GET /api/auth/register-mode`，`invite` 模式才显示邀请码输入框（§8.8）
- 登录成功后把 token 持久化（**用封装的存储模块**，不要直接 localStorage —— 小程序端没有它）

### 4. H5 端自动化验收（**这是唯一能自动化的部分**）

- 用 **Playwright** 对着**真后端**跑通：注册 → 登录 → 进入需要登录的页面
- **必须提供「红 → 绿」两次输出**（纪律见 `../../testing/README.md` §2）
- 贴出命令与真实输出

### 5. 小程序端验收（**手工项，如实标注**）

- 用微信开发者工具打开 `dist/build/mp-weixin`，**开启「不校验合法域名」**，把请求地址指向 `http://127.0.0.1:8080`
- 跑通：注册 → 登录 → 进入需要登录的页面
- **在报告里贴出你实际做的步骤与看到的界面**。这是手工验收项，**不要用"应该可以"糊过去**

## 7. 提示

- **小程序端与 H5 端的差异只有三处**：存储、请求、跳转外部链接。其余应共用同一份代码 —— 把这三处封装好，代码就不会分叉。
- **网盘链接在小程序端只能复制，不能跳外部浏览器**（[`../../adr/0011`](../../adr/0011-前端改用uni-app作为唯一前端.md) C1）。本期 M2 还不涉及网盘，但设计文案时记住这一点。
- 你**不要**去动 PWA 相关配置：PWA 在 uni-app 方案下优先级下降，由 L1 另行决定。

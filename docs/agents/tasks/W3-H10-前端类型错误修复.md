## 5. 错误清单（12 个，分三类 —— 全都要修，一个不能剩）

> 命令：`cd D:\demo\Hy论坛\web; npm run type-check`
> 修复前：**12 个错误，exit code 2**
> 修复后：**0 个错误，exit code 0**

### A 类：两个**用户可见的真 bug**（P0，本任务存在的理由）

```
src/pages/index/index.vue(62,3): error TS2322: Type 'RegisterModeResult' is not assignable to type 'RegisterMode'.
  Type '{ ok: true; mode: RegisterMode; }' is not assignable to type 'RegisterMode'.
src/pages/me/index.vue(114,3): error TS2322: 同上
```

**根因**：两处都是

```ts
const registerMode = ref<RegisterMode>('closed')      // 期望是字符串
...
registerMode.value = await fetchRegisterMode()        // ← 赋进来的是对象
```

于是模板里的比较全部失效：

- `v-if="registerMode !== 'closed'"` → **恒为真** → **管理员把注册模式切成 `closed` 之后，注册按钮仍然显示**
- `v-if="registerMode === 'closed'"` → **恒为假** → 「当前暂未开放注册」的提示**永远不出现**
- `result.ok === false`（**查询失败、状态未知**）那条"**绝不冒充业务状态**"的显式报错分支**等于白写**

**修法要求**：

1. 用 `result.ok` 分支：`ok` 时取 `result.mode` 赋给 `registerMode`；
2. `!ok` 时**必须把 `result.error` 让用户看到**（用页面已有的提示手段 —— 先看这两个页面现在怎么报错的，别引入新组件库）；
3. **不要**为了省事把它改成 `ref<RegisterModeResult>(...)` 然后在模板里做 `.mode` 判断 —— 那会把"状态未知"混进"业务状态"，正是这段设计要避免的事。

### B 类：`tsconfig.json` 的 `types` **覆盖了默认类型引入**（P1）

```
vite.config.ts(44,21):                error TS2591: Cannot find name 'process'.
playwright.config.ts(83,27):          error TS2591: 同上
e2e/probe-captcha.ts(45,9):           error TS2591: 同上
e2e/probe-captcha.ts(52,7):           error TS2591: 同上
src/utils/env.ts(17,36):              error TS2339: Property 'env' does not exist on type 'ImportMeta'.
src/utils/env.ts(20,36):              error TS2339: 同上
src/utils/env.ts(82,38):              error TS2339: 同上
src/utils/env.ts(83,34):              error TS2339: 同上
```

**根因**：`web/tsconfig.json` 里 `"types": ["@dcloudio/types"]`。
**`types` 是"替代"默认引入，不是"追加"** —— 写了它，`@types/node` 与 `vite/client` 就都不进来了。

**修法要求**：

- `process` 缺 `@types/node` → **需要新增这个 devDependency**（`npm i -D @types/node`）。注意它是 Node 语境的类型，**不应污染小程序端的 `uni` 类型环境**；
- `import.meta.env` 缺 `vite/client` → 可以加进 `types`，也可以在 `global.d.ts` 里声明。**二选一，说明你选哪个和为什么**；
- **推荐做法**：保持 app 侧 tsconfig 干净，**新建一个给 Node 语境文件用的 tsconfig**（覆盖 `vite.config.ts`、`playwright.config.ts`、`e2e/**`，`types: ["node"]`），并让 `npm run type-check` **两个都跑**。
  - ⚠️ 新文件用 `.json`，**不要用 `.mts` 之类** —— 避免碰到 `"type": "module"` 那一类加载问题（§3.2）。
  - ⚠️ **不许**只是把那些文件从 `include` 里删掉（§3.1）。

### C 类：两处空值安全（P1）

```
src/utils/env.ts(133,23): error TS18047: 'urlMatch' is possibly 'null'.
src/utils/env.ts(146,3):  error TS2322: Type 'string | null' is not assignable to type 'string'.
```

**修法要求**：修**真正的**空值路径（判空后走兜底、或让返回值保证非 null）。
**不要**用 `!` 硬断言蒙过去。若你判断某处逻辑上不可能为 null，**在注释里写清为什么不可能** —— 那也是一条有效证据，但要说出来。

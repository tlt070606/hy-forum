## 0. ⚠️ M5 只做"能拿到真证据"的那一半（需求方 2026-09-18 裁定）

`PLAN.md` 的 M5 是**内容安全 + 消息通知**，但 `sensitive_word` 表里现在是 **3 行占位符**
（`__PLACEHOLDER_敏感词库待替换__` / `__占位符1__` / `__占位符2__`），
而**真实词库只有需求方能定**（内容决策）。需求方裁定：**内容安全先不做**。

**所以本任务 = M5 的第二半**：

| 做 | 不做（挂前置，登记在案） |
|---|---|
| **消息通知**（点赞/评论/回复/关注 + 未读数） | **真实敏感词库的召回/误伤** —— 内容决策，不是代码 |
| **审核队列的出口**（放行 / 屏蔽） | ~~完整 DFA 词库~~（机制可做，词库不可做 → 归 H4，等词库到位） |
| **限流切面统一**（H2：429 与 `2002` 到底统不统一） | |
| 敏感词**机制**的调用点接线（用**测试词**验证触发路径） | |

**这意味着**：本任务里凡涉及敏感词的用例，**触发靠测试注入的词**（不是靠真实词库），
并在报告里**如实写明"这条验的是机制，不是词库内容"**。**不要把"机制通过"写成"内容安全达标"。**

## 5. L1 已答完的口径

| # | 口径 |
|---|---|
| 1 | **通知的写入必须在业务事务内**（点赞成功 → 同事务写通知）；**不得**用异步线程（本地可用版不做消息队列） |
| 2 | **自己操作自己 → 不产生通知**（`M5_no_self_notification`）；未读数是**当前用户**的未读，已读用单条或批量更新（二选一，报告里写明选了哪个） |
| 3 | **通知的 target 可能是已删内容**：查询时**不得**因为目标不存在就 500 —— 但**也不删通知**（用户的消息记录不该被别人的删除动作抹掉） |
| 4 | **审核出口两个方向**：放行（`status=1`）与屏蔽（`status=2`）**都要有**，且**都要留痕**（`admin_operation_log`，合规 C9） |
| 5 | **后台写操作必须留痕，且留痕失败要回滚业务改动**（`M6_every_admin_write_is_logged` / `M6_log_failure_rolls_back_action` 属 M6，但**本任务新增的后台端点现在就要遵守**） |
| 6 | **H2（本任务裁定）**：统一限流切面**必须设 `Retry-After` 响应头**；**"入口维度 429 / 业务动作维度 200 + 业务码"这个分层保持不变**（`技术方案.md` §8.7 已改准）——**不要把发帖的 `2002` 改成 429**（改它要动 M1 冻结的 `ErrorCode`，且会让前端按错的分支处理） |
| 7 | **`admin/**` 与前台隔离**：后台 token 不得访问前台接口（既有规则，别破坏） |
| 8 | **举报限流**：`M5_report_rate_limited_10_per_day` 的超限行为**按 §8.7 分层**（举报属业务动作维度 → 业务码 + HTTP 200，并**在报告里说明你选了哪个码**） |

## 3. 后端设计要点（先读再写，全是铁律约束）

1. **铁律 3**：`admin` 包只允许依赖 `common` + `domain`。审核帖子改 `post` 行走 domain 的 `PostMapper`；处理举报走 `ReportMapper`；封禁走 `UserMapper` + Sa-Token 踢人（`StpUserUtil` 属 common 可用）。**禁止**为了复用逻辑去调 `post`/`audit`/`user` 包的 Service —— 该下沉的下沉到 domain，该复制的复制（先例：`AdminAuthController#clientIp` 与前台各一份，注释互认）。
2. **敏感词刷新**：`admin` 改 `sensitive_word` 表后，必须让 audit 包的 `InMemorySensitiveTextChecker` 快照失效。走 **common 接口**（`SensitiveTextChecker` 增加 `refresh()` 端口或等价物），**不得** import audit 实现类。
3. **留痕红线（C9）**：每个写动作 = 业务 UPDATE + `admin_operation_log` INSERT **同一事务**；留痕失败整体回滚。动作编码登记进 schema 的 action 注释枚举（`POST_STATUS` / `REPORT_DISPOSE` / `USER_BAN` / `BOARD_*` / `SENSITIVE_WORD_*` / `REGISTER_MODE` / `INVITE_CODE`）。
4. **契约**：所有新端点先在 `docs/技术方案.md` §6.11 展开参数表 → 实现 → `scripts/export_openapi.ps1` 重导 → 前端（管理端与 uni-app 前台）分别登记。**管理端契约与前台契约是同一份 openapi.json**（tag 区分，不建第二份契约文件）。
5. **反向用例必须写**：前台 token 打管理端点 401（已有先例 `M5_comment_audit_401`）；admin token 打前台用户接口 401。
6. **封禁语义**：封禁 = `user.status` 置停用 + 立即踢下线（该用户全部 token 删除）；解封反向。封禁者不能是超级管理员以外的角色越权操作（本期只有一个 ADMIN 角色时，用例记为不适用并说明）。

## 4. 管理端前端（独立工程，不是 uni-app）

1. 新建 `admin-web/`（Vue 3 + Vite + TS 严格模式，**不用** uni-app）：管理后台只在桌面浏览器用，硬套跨端框架是负资产（PLAN M6 交付物原文"独立前端工程"）。
2. 结构对齐 `web/` 的纪律：`api/`（按域拆分 + `contract.ts` 登记 + 响应形状断言）、路由守卫（无后台 token 一律去登录页）、错误文案统一映射。**零代码分叉**：构建产物单份，后端地址走 env。
3. 页面清单（与验收一一对应）：登录、审核队列（帖子/评论两个 tab）、举报处理、用户管理（搜索/封禁/解封）、版块管理、敏感词管理、邀请码管理、系统配置（注册模式切换）。每页展示对应操作痕迹（`admin_operation_log` 最近记录）。
4. 部署：Nginx 加 `location /admin/`（静态直出，指向管理端 `dist/`）；`docs/ops/deployment.md` 同步补一节。

## 8. K3 白屏根因与修复记录（2026-10-03 定位并修复）

### 根因（一句话）

`web/src/main.ts` 顶部的教学注释**先于 import 出现了字面量 `createSSRApp`**。App 端编译器 `@dcloudio/uni-app-vite` 的 `uniMainJsPlugin` 用**朴素字符串替换**把入口里**第一处** `createSSRApp` 改名为 App 专用启动器（`code.replace('createSSRApp', 'createVueApp as createSSRApp')`，只替换第一处）—— 替换命中了**注释**，真正的 import 未被改名。App 于是用普通 `createSSRApp` 创建应用，uni 的 service 生命周期（onLaunch 等）永远不接通 → 静默白屏、零报错、零请求。**H5/小程序端没有这个 App 专用变换（该函数在那两端本就是正确 API），所以两端完全正常** —— 这正是「仅 App 端白屏」的原因。

### 修复

改写 main.ts 注释：标识符字面量不得先于 import 出现，并留下警示（含「本注释不得再写该字面量」的自我描述）。修复后编译产物中入口已正确改写为 `createVueApp`。

### 验证证据（2026-10-03）

1. 编译产物对比：修复前 app-service.js 中入口为 `e.createSSRApp(ga)`（变换未生效）；修复后为 `e.createVueApp(ga)`（变换生效）。
2. 真机（OPPO Reno9 5G / Android 15 / arm64）：修复资源推入 5.26 基座 → 论坛首页**完整渲染**，拉到后端真实数据（帖子、版块标签、点赞/评论/收藏/浏览计数、底部五 tab）。
3. MuMu 12（Android 15）：同资源**完整渲染**，连 OSS 图片与头像都正常加载。
4. 修复前对照：同一真机、同一基座，修复前资源必现白屏（多次冷启动 0 命中生命周期钩子探针）。

### 排查弯路留档（防止再犯）

- **一度误判为「模拟器 ARM 转译层」环境问题**：两处巧合误导 —— ① 官方 AVD 上基座内置 vue2 demo 起不来 v8 沙箱（`spinWaitPeer timeout`），那是真实存在但**与本应用无关**的转译层限制（vue2 demo 走 weex-v2 管线）；② MuMu 上当时被当作「基座 demo」测试的，其实是 HBuilderX 早期同步进 `apps/HBuilder` 目录的**我们自己的旧包**。真机复测同样白屏，推翻环境论。
- **`WeexRuntime getJSFMVersion failed` 是 vue3 启动路径的正常噪音**：weex-v2 握手探针在找 vue2 框架的 `getJSFMVersion()`，vue3 框架本来就不定义它，vue2/v3 混排日志时会误导排查方向。
- 空 tabBar 配置（已修，98f3cbc）是真实缺陷但不是白屏根因；排查中在最小复现环境里还观察到「App.vue 空 onShow 回调疑似致死」的现象，因与主因耦合未能单独定论——若未来再遇 App 端白屏，可从「入口改写是否生效」（grep 产物里的 createVueApp）查起。

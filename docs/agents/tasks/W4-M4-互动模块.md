## 5. L1 已答完的口径（**照办，不要再来问**）

### 5.1 楼中楼：**归并语义**（P1-3 已结案）

`comment.parent_id` **恒等于** `root_id`（其所属主楼 id）。
- 「回复楼中楼」→ 落库那行的 `parent_id = root_id = 主楼 id`（**归并到主楼**，不是指向楼中楼）。
- **必须有一个唯一写入口**做跨行校验（本项目禁外键，`CHECK` 无法跨行引用）：伪造 `parentId` 指向一个楼中楼时，实现要把它**归并**到主楼，而不是照抄传入值。
- 数据库侧的 `chk_comment_two_levels` 是**第二道**防线，不是唯一防线。

### 5.2 幂等：**条件更新 + 影响行数校验**（P1-4 定案）

禁止"先 SELECT 判断存在再 INSERT/UPDATE"。并发下 20 个线程必须只有一个成功，其余靠唯一索引冲突或影响行数=0 走"已存在"分支，**返回成功而非报错**（幂等语义）。

### 5.3 冗余计数：**同一事务内维护 + 不为负**（**本任务裁掉 P1-6，见下**）

- `post.like_count` / `post.collect_count` / `post.comment_count?` / `comment.reply_count` /
  `user.following_count` / `user.follower_count` / `user.post_count` —— **同一事务内**随关系表增减（§8.2）。
- **计数不得为负**：取消/删除路径必须是"递减且下限 0"（用 SQL 表达式或断言）。
- **P1-6 本来就是"计数校准任务的定义未决"，现在这样裁**：
  - **本任务只做"同事务维护 + 不为负 + 随机操作后自洽"**；
  - **"定时校准任务"从本任务的两条验收项里移出**，登记为独立交接项（归 M8/运维）——
    理由是它属于运维能力，塞进 M4 只会让 M4 又多一个"只进不出"的半成品。
  - 于是 `M4_counters_consistent_after_random_ops` 的判据变为：
    **随机增删序列跑完后，"冗余计数字段" == "关系表的实际行数"**（不需要校准任务参与）。
    `M4_delete_post_decrements_counters` 照旧做（删除后计数递减）。
  - **⚠️ 这条裁定的边界**：不要顺手实现一个定时任务；也不要因为"没有校准任务"就把计数改成实时 COUNT 查询
    （那违反 §8.2 的冗余计数设计）。

### 5.4 一处扩展（`common/**` 唯一允许的改动）：`@OptionalLogin`

现状：某些端点"登录可选"（未登录可看，登录后能看到更多），`media` 那边是用
`@AllowAnonymous` + 方法内显式取 `currentUserId` 实现的（**H13** 记录了这个"会扩散"的例外）。

**本任务允许**在 `common/web`（或 `common/**` 合适位置）收敛出 **`@OptionalLogin`**（或等价的参数解析器），
并**在新代码里使用它**：
- **允许**：新增这个注解/解析器；
- **不允许**：回头去改 `media`／`post` 的既有实现（那是他们的地盘）；
- **要求**：写一条测试证明"未登录时拿到空用户、已登录时拿到真实用户"——**不要**让"取不到就当 0"这种静默错法有机会存在。

### 5.5 关键口径表（照办）

| # | 口径 |
|---|---|
| 1 | 未登录访问**关注流** → 引导登录（`401`），不是空列表 |
| 2 | **禁止关注自己** → 明确拒绝（错误码按 §6.1 选最贴的；**在报告里说明你选了哪个、为什么**） |
| 3 | 关注是**双向计数各 +1 一次**（`following_count` / `follower_count`），且**各只加一次** |
| 4 | 收藏列表长度必须 == `post.collect_count`（**随机 100 次操作后**仍成立） |
| 5 | 主楼预览**前 2 条**楼中楼（`reply_count` 是总数，不是预览数） |
| 6 | 全部流/关注流**按时间倒序**；分页 `size` 硬上限 **20**（与 M3 一致） |
| 7 | 关注流只含**已关注用户**的帖子，且要**过滤待审帖**（`status=0`）与已删帖 |
| 8 | 计数与关系表**在同一事务**内；跨模块只读 `domain` 实体 |

## 7. 完成定义（DoD）

### 7.1 逐字测试名（**映射表已登记，名字不许改**）

| # | 测试名 | 断言要点 |
|---|---|---|
| 1 | `M4_like_idempotent_concurrent` | 20 线程并发 → 行数=1、`like_count`=1；**自证真并发**（`readyThreads()==20`） |
| 2 | `M4_collect_idempotent_concurrent` | 同上，作用于 `post_collect` |
| 3 | `M4_uncollect_idempotent` | 重复取消 → 行数=0、**计数不为负** |
| 4 | `M4_follow_idempotent` | 行数=1、双方计数各 +1 **一次** |
| 5 | `M4_follow_self_rejected` | → 拒绝 |
| 6 | `M4_collect_list_matches_count` | 随机 100 次后长度 == `collect_count` |
| 7 | `M4_comment_no_third_level` | ① 回复楼中楼 → 落库 `parent_id = root_id = 主楼id`；② **对抗性**：伪造 `parentId` 指向楼中楼 → 仍归并；③ 直接 `INSERT` 非法组合 → 被 `chk_comment_two_levels` 拒（**错误码 3819**） |
| 8 | `M4_comment_reply_count_consistent` | 主楼计数 == 实际楼中楼数 |
| 9 | `M4_comment_list_previews_two_replies` | 每主楼带 **2** 条预览 |
| 10 | `M4_feed_follow_only` | 只含已关注用户的帖子（且过滤待审/已删） |
| 11 | `M4_feed_all_ordered_by_time` | 时间倒序 |
| 12 | `M4_feed_follow_requires_login` | 未登录 → 引导登录 |
| 13 | `M4_counters_consistent_after_random_ops` | **按 §5.3 的判据**：随机增删后冗余计数 == 关系表行数 |

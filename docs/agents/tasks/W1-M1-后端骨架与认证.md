## 5. 完成定义（DoD）—— 必须贴出真实命令输出

1. **编译**：`mvn -q -DskipTests package` 成功（JDK 21）
   > 命令前必须设 `$env:JAVA_HOME='D:\develop\jdk21'`（宿主进程仍是旧环境）。
   > **并要求在 pom 里加 `maven-enforcer-plugin` 的 `requireJavaVersion [21,)`** —— 这样万一 JDK 用错，会得到一句明确的"需要 21"报错，而不是难懂的 `invalid target release`。这是把"环境踩坑"变成"自解释失败"的手段。
2. **红 → 绿**：先贴**一条测试失败**的命令输出，再贴它**通过**的输出（证明测试真的在测东西；纪律见 [`../../testing/README.md`](../../testing/README.md) §2）
3. **`mvn test` 全绿**，且包含以下**全部**测试（名字必须一致，否则覆盖率脚本查不出来）：
   - `M1_register_login_me_flow`　注册 → 登录 → `GET /api/user/me` 通链，`code=0`
   - `M1_response_envelope_shape`　统一响应与分页结构符合 §6.1
   - `M1_error_codes_match_contract`　§6.1 的 12 个错误码逐一命中
   - `M1_captcha_wrong_returns_1003`
   - `M1_captcha_ttl_is_300s`　Redis 键 TTL = 300s
   - `M1_duplicate_username_returns_1001`
   - `M1_weak_password_rejected`　8–32 位且含字母+数字
   - `M1_agree_protocol_required`　`agreeProtocol=false` → 拒绝（合规 C1）
   - `M1_register_mode_open_allows`
   - `M1_register_mode_invite_requires_code`　无码拒绝、有效码通过
   - `M1_register_mode_closed_rejects`
   - `M1_admin_unaffected_by_register_mode`　`closed` 下管理员仍可登录
   - `M1_password_never_returned`　响应中不出现密码/哈希字段
   - `ARCH_no_cross_module_dependency`　ArchUnit：七个业务包互不依赖（`技术方案.md` §3.3 v1.8 口径）
   - `ARCH_no_heavy_components`　依赖树无 ES / MQ / 注册中心客户端（铁律 7）
4. **导出接口契约**：把 `/v3/api-docs` 的产物保存为仓库根 `openapi.json` 并纳入版本库。
   > 这是**接口的唯一事实来源**，由你产出、由 L1 冻结；**不要手工编辑它**。
5. **注册模式必须数据驱动**：`register_mode` 从 `sys_config` 表读取；**切换后行为立即变化，无需重启**（§8.8）。若你加了缓存，必须说明失效策略。
6. **交付说明**（写在报告里）：改了哪些文件 / 哪些测试未写或未通过 / 哪些行为未验证。

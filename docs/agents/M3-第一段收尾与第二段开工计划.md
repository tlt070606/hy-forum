## 2. **九项裁决（本文件最重要的部分 —— 已定，勿再讨论）**

子代理报告 §7 提了九项。逐条裁决如下，**执行时照办即可**：

| # | 事项 | **裁决** |
|---|---|---|
| 1 | 10 个新测试名未入映射表 | **登记**。名字见子代理报告 §3.3；`M3_post_rate_limit_triggers_2002` 是 H1 点名的 |
| 2 | `OssProperties` 归属 + 两份 OSS 配置 | **上移到 `com.hyforum.common.oss.OssProperties`**，`post` 与 `media` 都注入它。理由：同一个配置前缀若由两个包各自绑，就是"同一事实两处映射"，迟早漂移。**不要**让 post 依赖 media 或反之（铁律 3） |
| 3 | 浏览量测试归 M3 还是 M4 | **两条都移到 M3 段**（`M4_view_count_not_direct_update`、`M4_view_count_flushed_after_interval` → 登记 `M3_view_count_increments_in_redis`）。**但注明**：`@Scheduled` 的**定时回写**本身仍未被"等 5 分钟"验证过，那一半归 M4 |
| 4 | `2002` 该 HTTP 200 还是 429 | **保持 HTTP 200 + body `2002`**（`ErrorCode` 是 M1 冻结的唯一定义，改它要 CR）。**§8.7 的措辞要改准确**：IP 维度超限 → **429**（M1 已实现）；**发帖维度**超限 → 业务码 `2002` + HTTP 200。两者不是同一层的东西，别混。是否统一为 429 归 **M5 的统一限流切面**（H2）一起决定 |
| 5 | 可选鉴权的实现例外（`@AllowAnonymous` + 显式取 currentUserId） | **接受**，但**登记为 H13**：把它收敛成 `common/web` 的 `@OptionalLogin` 支持是独立小任务，不阻塞 M3 |
| 6 | PUT 是"覆盖"还是"PATCH" | **保持覆盖**（省略即清空）。理由：与"内容变更 → 重审"的状态机一致（PATCH 语义会让"哪些字段算变更"变模糊，正是审核绕过路径的来源） |
| 7 | `M3_copy_payload_format` 没有契约出口 | **保持**（后端只提供工具类 + 单测锁定格式，不下发）。理由：复制文案由前端 `copyText` 封装生成，下发会造成"同一条帖子在不同端文案不同"；格式的唯一锁定靠单测 |
| 8 | H12（`GET /api/posts/abc` → 500 而非 400） | **修**，归第二段任务书（`GlobalExceptionHandler` 加 `MethodArgumentTypeMismatchException` → 400）。**属于 M1 交付物的既有缺陷**，加这一条要跑全量回归 |
| 9 | 敏感词能力仍是 M1 朴素实现 | 无需新裁决，已在 **H4**（归 M5）。M3 通过 `common.audit.SensitiveTextChecker` 接口调用，M5 换实现时 post 侧零改动 |

### 4.1 一个必须知道的脆弱点

OSS 回调的入口借用了 ECS 上**别人的静态站**（`personal`，`/var/www/personal`）：
新增 `DocUiResourceConfig` 之外，**在 `/etc/nginx/sites-available/personal` 里加了一行 `include`**。

> **若将来有人重新部署那个站、或覆盖了那份 nginx 配置，`include` 会消失**，
> 现象是"OSS 上传成功但图片不落库"——**看起来像后端 bug**。排查时先看那行在不在。

## 5. 今天新踩的坑（**都已实测，别再犯**）

| # | 坑 | 真相 |
|---|---|---|
| 1 | PowerShell 5.1 **不允许 `if` 作内联表达式** | `"x" + (if ($a) {..} else {..})` 解析失败。要用 `$v = if(...){..}else{..}` 先赋值 |
| 2 | `python -c @"..."@` 里的**双引号被吞** | 内联 python 一律**写成 `.tmp\*.py` 文件再跑**（本项目已多次栽在这） |
| 3 | `git checkout -- <file>` 会**冲掉同一文件里自己未提交的修复** | 用破坏性还原前先 `git status`；或"复制到 `.tmp` → 探针 → 从副本还原" |
| 4 | PowerShell `Set-Content -Encoding UTF8` **加 BOM 且丢行** | 改文件**只用文件编辑工具**（[`../../web/lw长期记忆.md`](../../web/lw长期记忆.md) §3.2 第 6 条已写明，我仍踩了） |
| 5 | **`git show --stat` 的作者字段无法归因** | 本仓库所有提交的作者/提交者都是同一个值（`tlt0606`）。**没有内容级证据不要做归因**（见 [`工作计划.md`](工作计划.md) §7.1 的撤回记录） |
| 6 | `.ps1` 必须 UTF-8 BOM | 纯 ASCII 时 BOM 不影响正确性，但**按 §7.1 规矩仍要补**（字节前置，不重写内容） |
| 7 | 任务交付后**不要再给同一个子代理发消息** | 那等于让已结束的任务在**没有任务书**的情况下重开一轮。追加工作 → **写新任务书** |

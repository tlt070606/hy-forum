### 3.1 我采用的读法（任务书 §8 允许"写读法 + 理由继续做"的部分）

1. **禁止关注自己的错误码选 `400`（不用 403/404）**
   - 不是"你无权对某个存在的对象做这件事"（403 的语义），而是"这个请求本身不成立"；
     也不用 404 —— 那暗示"用户不存在"，而用户明明存在，就是你自己。
   - 与契约的关系：§6.1 只列了码的含义，没规定这一场景用哪个，因此属实现裁决范畴。
2. **"回复已删除/不可见的评论"返回 `404`（不是 400）**
   - 与"帖子不存在 → 404"保持一致；用 400 会把"对象不存在"误报成"参数写错了"。
   - 跨帖回复也按 404 处理，**且刻意不区分**"不存在"与"属于别的帖子"—— 区分等于泄露
     "这个评论 id 存在，只是不属于这篇帖子"。
3. **`replyToUserId` 不接受客户端传值，由服务端按 `parentId` 推导**
   - DTO 里保留了该字段（契约兼容、前端可照传）但不读它。理由：被回复者由"回复了哪条评论"
     唯一确定；让客户端指定等于允许"我的评论显示成回复了别人"，而 M5 的通知正是按它发的。
   - 推导规则：回复主楼 → 主楼作者；回复楼中楼 → 那条楼中楼记着的 `replyToUserId`（没有则其作者）；
     被回复者就是自己 → 存 `null`。
4. **评论本期不接敏感词过滤，一律落 `status=1`**
   - §8.6 第 2 条要求命中置 0 进待审队列，而**评论的审核出口**（`PUT /api/admin/comments/{id}/status`）
     归 M6。现在置 0 会造出一个**只进不出的队列**，与 §8.6 反复强调的"队列必须有出口"直接冲突。
     因此本任务不实现它，登记为交接事项（M5/M6 接出口时一并接敏感词）。
5. **`/api/feed` 的 `sort=hot` 一并实现**
   - §8.5 说全部流"额外提供热门排序入口"。`type` 与 `sort` 非法取值一律 400，
     不静默回落默认值（静默回落会让前端的"热门"按钮不生效却不报错）。
6. **删帖收尾的评论行做逻辑删除、关系行做物理删除**
   - 关系表（`post_like`/`post_collect`/`comment_like`）无 `is_deleted`，取消即物理删除，
     留墓碑会让 `计数 == 关系表行数` 永久不成立 → 删帖收尾也必须物理删除；
   - `comment` 表本身是 `@TableLogic`（实测 `DELETE` 被翻译成 `UPDATE ... SET is_deleted=1`），
     因此随表设计做逻辑删除。对它的正确等式是 `comment_count == COUNT(... WHERE is_deleted=0)`。
7. **`GET /api/feed` 放在 `interaction` 包**
   - 它属于 §6.5，但关注关系归本模块，而 `post/**` 不在 M4 写权内；查询只用 `domain` 的
     实体与 Mapper，没有跨模块调用（已用 ArchUnit 用例验证）。

### CR-M4-3 删帖后的互动收尾需要 L1 裁决"谁调、何时调"

- **缺什么**：`M4_delete_post_decrements_counters` 要求"逻辑删除后计数递减"，但 M3 的
  `PostService.delete` 只递减 `user.post_count` 与 `board.post_count`，**不碰**
  `like_count`/`collect_count`/`comment_count`。那些文件属 W3-M3b 写权，M4 无权改。
- **我的做法**：把收尾逻辑做成**公开入口** `InteractionService.onPostDeleted(long postId)`，
  由 `post` 模块在删帖时调用一次（调用方向 `post → interaction`，不引入跨模块依赖，
  但**必须由 L1 裁决**是否允许这种调用方向；铁律 3 的字面是"业务模块之间只允许依赖
  common 与 domain"）。
- **⚠️ 时机是硬约束（实测）**：必须在 `post.is_deleted` 置 1 **之前**调用。
  因为 `Post` 带 `@TableLogic`，MyBatis-Plus 会给**每一条 UPDATE** 自动附加 `AND is_deleted = 0`；
  帖子一旦逻辑删除，计数 UPDATE 影响 **0 行**、静默什么都不做，而关系行是物理删除的照样会删 ——
  结果是最坏的一种：**关系表空了、计数还留着旧值**。实测证据（临时用例已删，只留结论）：
  ```
  DIAG D 已逻辑删除的帖子 update 影响行数=0   like_count=0（未被写入）
  DIAG A/B/C 未删除时：影响行数=1，多赋值与 IF 表达式均正常生效
  ```
  代码里已加 `affectedPost == 0` 时 `log.error` 的显式告警，不让它静默。
- **建议**：批准后由 M3 在 `PostService.delete` 里于 `postMapper.deleteById` **之前**调用一次；
  或由 L1 裁定改由应用事件（`ApplicationEventPublisher`）解耦。**在那之前，M4 这条验收项
  的"接线"部分不算完成**，用例证明的是"这段收尾逻辑本身是对的"。

### CR-M4-4 **M3 既有缺陷**：UNSIGNED 列的 `GREATEST(col - 1, 0)` 会直接报错（不是"兜底"）

- **现象与根因**：`PostService.delete` 用
  `SET post_count = GREATEST(post_count - 1, 0)` 给 `post_count`（`INT UNSIGNED`）兜底。
  但 **MySQL 会先在无符号域里算出 `post_count - 1`**，当 `post_count = 0` 时直接抛
  `ERROR 1690 (22003): BIGINT UNSIGNED value is out of range`，**根本轮不到 `GREATEST`**。
- **实测对照**（本项目 MySQL 8.0.34 真机，临时表）：

  | 语句 | 结果 |
  |---|---|
  | `UPDATE t SET c = GREATEST(c - 1, 0)`（c=0） | ❌ `ERROR 1690` |
  | `UPDATE t SET c = IF(c > 0, c - 1, 0)`（c=0） | ✅ `c = 0` |

- **触发条件**：删一条"作者 `post_count` 已经是 0"的帖子 → **删帖接口 500**。
  这是**既有缺陷**（不是我引入的）：我在写用例时先直接 `INSERT` 造帖（`post_count` 仍为 0），
  于是删帖直接 500，暴露了它。后来我把用例改成走发帖接口（`post_count` 正确为 1），
  用例才在测"计数回退"而不是在测这个缺陷。
- **建议**：把 `PostService` 里两处 `GREATEST(post_count - 1, 0)` 改成 `IF(post_count > 0, post_count - 1, 0)`。
  **M4 自己的所有递减已经统一用 `IF(...)` 写法**（`like_count`/`collect_count`/`comment_count`/
  `reply_count`/`follow_count`/`fans_count`），并在注释里写明为什么不用 `GREATEST`。
- **影响**：`post/**`（W3-M3b 写权），**M4 不越界去改**。

### CR-M4-5（文档一致性，低风险）两处命名/形状差异

1. 任务书/技术方案说 `following_count`/`follower_count`，schema 是 `follow_count`/`fans_count`（见 §3.2）。
2. §6.3 的 `/api/user/collections` 我返回了一个新形状 `CollectionItemVO`（契约未细化该列表形状）。

### CR-M4-6（建议收敛，非阻塞）`post` 的 VO 在 `interaction` 里被复制了一份

## 5. 关键证据

### 5.1 🔴 一处重要的**断言修正**：不要照抄幂等样板的"19 个线程必须抛异常"

幂等样板 `IdempotencySampleTest` 断言"另外 19 个线程必须拿到 `DuplicateKeyException`"，
理由是"只断言行数的话，一个把所有插入都吞掉的实现也能通过"。**那条断言对样板成立，对 M4 不成立**：

- 样板的 20 个线程执行的是**裸 `jdbcTemplate.update`**，没有任何 catch —— 异常当然会冒出来；
- 业务实现按 §5.2 的**原话**"其余靠唯一索引冲突或影响行数=0 走'已存在'分支，
  **返回成功而非报错**"，必须把 `DuplicateKeyException` **catch 掉并翻译成成功**，
  异常根本到不了调用方。

我第一版照抄了样板的断言，结果是"**正确的实现被判成失败**"（`expected: 19 but was: 0`），
而且我一开始误以为是自己实现坏了 —— 排查过程中先怀疑了唯一索引、再怀疑了驱动翻译、
最后用"逐层打印"才定位到 `[DIAG-likePost] 命中唯一键，走幂等分支` 这行日志。

**修正后的断言**（连同"不能因此变弱"的补偿）：
1. 断言 **所有 20 个线程都返回成功**（这才是契约要求的行为）、`failureCount()==0`、
   行数=1、`like_count`=1、`readyThreads()==20`；
2. **新增两条更硬的用例**补上"是否真的走了幂等分支"这个被放弃的证明：
   `M4_like_idempotent_does_not_double_count` / `M4_collect_idempotent_does_not_double_count` ——
   预先手工落一行关系行、并把计数设成**哨兵值 99 / 77**，再让 20 个线程并发调用。
   **任何"误加"都会让哨兵变成 99+ / 77+，无处隐藏**；而一个"每次都 +1"的实现会直接得到 119/97。
   变异验证证明它确实有区分力：注入"重复点赞不 return、继续加计数"后，
   这条用例报 `expected: 99 but was: 119`。

> **为什么这值得写进报告**：这是"样板断言被无差别复制"的典型陷阱 ——
> 复制的是**结论**，而不是**结论成立的前提**（那里没有 catch）。若不拆开检查就改弱断言，
> 会关掉真正的检查；若照抄，会把正确实现判红。正确处理是**换一条更有区分力的断言**。

## 6. H6 专项：jqwik 与 Surefire 配合的**四个坑**（任务书要求写明，这本身是产出）

> 任务书 §6 说"jqwik 与 Surefire 配合若有坑，在报告里写明"。实测**有四个坑**，
> 其中第 1 个是**"写了但一条都没跑"**，最危险。

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| **1** | 🔴 **`@Property` 方法上不能有任何 JUnit 注解（连 `@DisplayName` 都不行）** | jqwik **静默跳过**该属性；**构建仍然 `BUILD SUCCESS`**，Surefire 汇总只多一个 Skipped：`Tests run: 3, Skipped: 3` —— **属性测试一条都没跑，却显示全绿** | 描述写 JavaDoc。实测原文：`A @Property method must not have JUnit annotations: [@org.junit.jupiter.api.DisplayName("...")]` |
| **2** | **`@SpringBootTest` 的注入对 `@Property` 方法无效** | 属性方法里的 `@Autowired` 字段、基类的 `jdbcTemplate` / `tableCleaner` **全是 null**（实测依次报 `this.tableCleaner is null`、`this.jdbcTemplate is null`、`this.interactionService is null`、`CONTEXT is null`）。因为 Spring 的注入是 JUnit 5 的 `SpringExtension` 做的，而 jqwik 走自己的引擎 | 用 jqwik 的 `@BeforeContainer` **手动 build 容器**（`SpringApplicationBuilder(...).profiles("test").web(NONE).run()`），放到静态字段上供属性方法使用 |
| **3** | **`@BeforeTry` 与 Spring 注入时机不同步** | 同上第 2 条的早期表现：想在 `@BeforeTry` 里用注入的 `DataSource` 建基线 → 拿不到 | 容器与 JDBC 都自己造；不依赖注入字段 |
| **4** | **`@ForAll("provider")` + `@Size` 组合会类型不匹配** | `IllegalArgument argument type mismatch` | 让 provider **直接产出 `Arbitrary<List<T>>`**（`.list().ofMinSize(1).ofMaxSize(60)`），不要"给元素再套 `@Size`" |

**另加一条工程提醒**：属性测试的**每个 try 都要重建基线**（`@BeforeTry`/`@AfterTry` 清表），
否则上一条随机序列的数据会污染下一条，而失败时 jqwik 给出的反例会看起来毫无道理。
基类的 JUnit `@BeforeEach` 清表**不会**作用于属性方法。

**代价（如实记录）**：因为要自己起容器，属性测试的 Spring 上下文与 JUnit 测试的**不共享**，
本类会多启动一次 Spring（约 6 秒，实测 18–20 秒跑完 60 次属性调用）。
这是"必须另起一次"而不是"可以优化"的事 —— 除非放弃 jqwik、改回手写随机循环，那就不再是属性测试。

## 8. 踩坑清单（供后来者，尤其是 M5/M6）

| # | 坑 | 现象 | 根因与修法 |
|---|---|---|---|
| 1 | **同名 Controller 让整个 Spring 上下文起不来** | 23 个用例全 `IllegalStateException: Failed to load ApplicationContext`，看起来像基建坏了 | Spring 默认 bean 名取自**类简单名**，与包名无关。`com.hyforum.user.controller.UserController` 与 M1 的 `com.hyforum.auth.controller.UserController` 撞名 → `ConflictingBeanDefinitionException`。**改名 `UserProfileController`** |
| 2 | **MyBatis-Plus 的 `in(...)` 遇空集生成非法 SQL** | "我的收藏"为空时接口 **500**，`You have an error in your SQL syntax ... near ') AND is_deleted=0'` | `selectBatchIds` 拿到空列表会生成 `IN ()`。**必须先判空提前返回**。只在"有数据"的路径上测永远看不到它 |
| 3 | **MySQL 不支持 `IN/ALL/ANY/SOME` 子查询里带 `LIMIT`** | 主楼评论列表 **500**：`This version of MySQL doesn't yet support 'LIMIT & IN/ALL/ANY/SOME subquery'` | 改用窗口函数 `ROW_NUMBER() OVER (PARTITION BY root_id ORDER BY ...)` 取前 2 |
| 4 | **`LambdaUpdateWrapper.setSql` 是"设置"不是"追加"** | 三个计数只有最后一个生效（症状：删帖后 `like_count` 不归零、收藏与评论却归零了，像"只漏了一个字段"） | 多个赋值**必须拼成一条带逗号的 `setSql`** |
| 5 | **`GREATEST(col - 1, 0)` 给 UNSIGNED 列兜底会报错** | `ERROR 1690 BIGINT UNSIGNED value is out of range` | MySQL 先算减法。改成 `IF(col > 0, col - 1, 0)`（CR-M4-4，M3 也有同一个缺陷） |
| 6 | **`@TableLogic` 会让"删后更新计数"静默失效** | 计数 UPDATE 影响 0 行、什么都不做，而关系行照样被物理删除 → **关系表空了、计数还在** | MP 给每条 UPDATE 自动加 `AND is_deleted = 0`。收尾必须在**逻辑删除之前**调用（CR-M4-2） |
| 7 | **测试库名有两个来源，且环境变量那条路是断的** | 测试静默连上共享库；清表工具去清**另一个**库；表现为"30 线程全插入成功"这种像实现坏了的假红 | 见 CR-M4-1。M4 用 `@TestPropertySource` 显式钉死 url + 显式传清表工具的期望库名 + `@BeforeEach` 断言当前库 |
| 8 | **jqwik 的四个坑** | 见 §6（第一条是"写了但没跑还全绿"） | 同上 |
| 9 | **`mvn -Dxxx=yyy` 在 PowerShell 5.1 里必须整体加引号** | `No plugin found for prefix '.repo.local=D'`（Maven 把 `-D` 后的内容当插件前缀解析） | 写成 `'-Dmaven.repo.local=D:\demo\.m4repo'`。任务书里给的命令没有这个问题，但一旦路径/值里出现 `.` 开头就容易踩 |
| 10 | **原生命令的 stderr 会中断 `.ps1`** | 脚本在 `$ErrorActionPreference='Stop'` 下被一行 JVM warning 直接终止，测试其实跑了、输出却被吞 | `2>&1` + 局部把 `ErrorActionPreference` 放松 |
| 11 | **`.ps1` 不带 BOM → 中文路径变乱码** | `Cannot find path 'D:\demo\Hy璁哄潧\...'` | 加 UTF-8 BOM（本项目已有此规矩，我又踩了一次：文件写入工具会丢 BOM） |
